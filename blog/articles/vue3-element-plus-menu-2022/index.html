Vue3 中封装 Element Plus 无限级菜单的基本思路

2022-09-17
Vue前端基础

后台系统里经常会有侧边菜单。

普通菜单只有一两级还好，一旦菜单来自接口，并且层级不固定，就需要封装一个支持无限级的菜单组件。

在 Vue3 和 Element Plus 中，实现这类菜单的关键是两点：统一数据结构，递归渲染菜单项。

这类组件看起来只是 UI 递归，但实际项目里通常还会牵涉路由、高亮、权限、图标、折叠状态和接口数据清洗。如果这些逻辑边界不清楚，菜单组件很容易越写越重。

权限过滤放在哪里

菜单权限过滤最好在数据进入组件前完成，而不是在递归模板里到处判断。

最后一行用于去掉没有路径、也没有可见子菜单的空节点。权限过滤如果不处理空父级，侧边栏里很容易出现点不开的菜单。

路由跳转和 index

Element Plus 的 el-menu 支持 router 模式，这时 index 通常会作为路由路径使用。但实际项目里，index 不一定总等于 path。

我更倾向于明确约定：

  • 如果开启 router，index 使用可跳转路径
  • 如果不开启 router，点击事件里根据 path 手动跳转

不要一会儿用 code，一会儿用 path。菜单高亮和跳转逻辑一旦混乱，后面会很难排查。

如果 path 为空，说明它可能不是可点击菜单项，要在数据层提前处理清楚。

实际项目要注意什么

无限级菜单看起来通用，但实际项目里还要考虑：

  • 菜单权限过滤
  • 路由地址和菜单 index 的对应关系
  • 图标动态渲染
  • 折叠时标题显示
  • 刷新页面后高亮当前路由
  • 菜单数据为空时的兜底

这些逻辑不要全部塞进递归项里，否则组件会越来越重。

还有两个边界经常被忽略：

  • 菜单层级过深时，交互体验会变差
  • 菜单数据可能存在循环引用或重复 index

小结

Vue3 封装 Element Plus 无限级菜单，本质是树形数据加递归组件。

先把菜单数据整理清楚，再把外层配置和单项渲染拆开，后续接权限、路由和图标都会更容易维护。

我现在做这类菜单，会把它拆成三层：接口数据转换、权限和路由规则、递归 UI 渲染。三层分开以后，菜单组件本身就不会承担太多业务细节。
