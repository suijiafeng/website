前端主题切换怎么做：从深色模式到多主题

2022-10-05
前端基础CSS

主题切换是很多前端项目都会遇到的需求。

最常见的是浅色模式和深色模式，也有一些后台系统会支持品牌色切换、多套皮肤或节日主题。

它看起来是视觉问题，实际会影响 CSS 组织方式、组件封装和长期维护成本。

主题系统做得好，后面增加深色模式、多品牌、节日皮肤都比较自然；做得不好，就会变成到处覆盖样式、到处写特殊判断。

主题切换的核心是什么

主题切换不是简单地把背景色改成黑色。

真正需要管理的是一组设计变量：

  • 主色
  • 背景色
  • 文本色
  • 边框色
  • 阴影
  • 禁用态颜色
  • 成功、警告、错误等状态色

如果这些颜色散落在各个 CSS 文件里，后面改主题会非常痛苦。

所以主题切换的第一步不是写切换按钮，而是先定义 token。不要让组件直接依赖具体颜色，而是依赖语义变量。

组件库主题要单独处理

如果项目使用 Ant Design、Element Plus 这类组件库，主题切换不能只改业务 CSS。

还要看组件库本身支持哪种方式：

  • 是否支持 CSS 变量
  • 是否提供暗黑主题
  • 是否支持运行时切换 token
  • 是否需要单独引入主题样式文件

最理想的情况是：业务样式和组件库主题都由同一套变量或 token 驱动。

以 Element Plus 为例，它本身有一套 CSS 变量。如果业务样式用自己的变量，组件库用另一套变量，就要建立映射关系，而不是各写各的。

这样业务按钮、组件库按钮至少能跟随同一个主色变化。

不建议写两套完全独立样式

有些项目会写 light.css 和 dark.css 两套完整文件。

短期看很直接，长期容易出现问题：

  • 两套样式内容重复
  • 新组件容易漏写暗黑样式
  • 修改一个细节要改两处
  • 主题之间差异越来越难控制

如果只是颜色不同，CSS 变量通常更容易维护。

当然，也不是所有差异都适合用变量解决。如果主题之间布局结构、插图资源、动效规则都完全不同，那可能已经不是“主题切换”，而是不同页面皮肤或不同产品形态。这个时候硬塞进一套变量里，反而会让系统复杂。

图片、阴影和图表也要考虑

深色模式里最容易漏的是非 CSS 颜色：

  • 图片和 logo 是否适合深色背景
  • 图表颜色是否仍然可读
  • 阴影在深色背景下是否看得见
  • 代码高亮主题是否同步切换

图表库也要接入主题，否则页面整体变暗，图表仍然是亮色，会显得很突兀。

可访问性和对比度

主题切换不是只看“好不好看”，还要看文字对比度是否足够。

深色模式里常见问题是正文灰度太低，长时间阅读很吃力；浅色模式里则可能是浅灰文字过淡。设计 token 时要把主文本、次文本、禁用文本分清楚。

不要只通过颜色表达状态。错误、成功、警告最好同时有文字、图标或明确上下文，避免用户只能靠颜色判断。

小结

主题切换的关键是提前抽象颜色变量，而不是到处写固定色值。

简单项目可以用 class + CSS 变量 实现。复杂项目还要结合组件库主题能力，让业务样式和组件库样式保持一致。

我现在做主题系统，会先设计语义 token，再处理主题 class、持久化、系统偏好和首屏防闪。切换按钮只是最后一步，真正的工作是让颜色、组件、图表和状态都能被同一套主题规则驱动。
