jQuery 事件委托：列表越来越长时，别给每个按钮都绑事件

2018-06-19
JavaScript前端基础

虽然新项目越来越多用 Vue、React，但很多活动页、后台老页面、运营页面里，jQuery 仍然很常见。

jQuery 里最值得掌握的技巧之一是事件委托。它不只是面试题，在动态列表、表格操作、无限加载里都很实用。

先看直接绑定的问题

页面初始化时已有按钮可以正常点击。但如果后面通过 Ajax 动态追加列表：

新按钮没有绑定事件。

你可以追加后再绑定一次，但列表越来越复杂时，很容易重复绑定或漏绑。

事件委托写法

事件绑定在 .list 上，点击 .delete-btn 时，事件冒泡到 .list，jQuery 再判断事件源是否匹配选择器。

这样后续动态添加的按钮也能响应。

不是所有事件都适合委托

点击事件很适合委托。mouseenter、mouseleave、一些表单事件则要看具体表现。

另外，如果父容器里匹配元素非常多，选择器又复杂，也要注意性能。委托不是万能，只是比给大量动态节点逐个绑定更合适。

小结

事件委托的核心是事件冒泡。

它解决动态节点绑定和大量列表事件的问题，也能减少事件处理函数数量。面试常问它，是因为它能看出你是否理解 DOM 事件模型。项目里用它，要注意委托范围、事件目标、阻止冒泡和解绑。
