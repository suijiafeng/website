进程和线程：写前端也绕不开的操作系统基础

2019-01-09
杂项

进程和线程是计算机基础里很常见的面试题。

刚做前端时，可能觉得这些离页面很远。可真到项目里，浏览器多进程、Node 单线程、Web Worker、页面卡顿、服务端并发，这些问题都会把你拉回到操作系统基础上。

理解进程和线程，不是为了背定义，而是为了知道程序到底怎么运行。

什么是进程

进程可以理解为正在运行的程序实例。

打开一个浏览器、启动一个 Node 服务、运行一个构建命令，操作系统都会为它分配资源。进程有自己的内存空间、文件句柄、环境变量等。

不同进程之间默认是隔离的。一个进程崩了，不应该直接把另一个进程的内存改坏。

浏览器里，一个标签页、渲染进程、插件进程、GPU 进程这些概念经常被提到，本质上都是为了隔离和稳定。

什么是线程

线程是进程里的执行单元。

一个进程可以有多个线程，它们共享进程的内存空间，但各自有执行栈。

共享内存带来方便，也带来风险。多个线程同时读写同一份数据，就可能出现竞争问题。

这也是为什么多线程编程里经常要考虑锁、同步、原子操作。

并发和并行

并发是看起来同时处理多个任务。

并行是真正同时执行多个任务。

单核 CPU 上也可以并发，操作系统通过时间片切换，让多个任务轮流执行。多核 CPU 才能让多个任务真正并行执行。

JavaScript 在浏览器主线程里一次只能执行一段 JS，但浏览器整体不是单线程。网络、定时器、渲染、事件处理背后都有不同模块协作。

上下文切换

CPU 从一个线程切到另一个线程，需要保存当前状态、恢复另一个线程状态，这叫上下文切换。

切换不是免费的。线程太多时，CPU 可能花很多时间在切换上，真正执行任务的时间反而变少。

这也是为什么服务端并发不是“线程越多越好”。

JavaScript 为什么说是单线程

通常说 JavaScript 是单线程，指的是 JS 执行主线程。

这样的代码会卡住页面，因为主线程被占满了，用户点击、渲染更新都没机会执行。

异步请求不会阻塞等待，但回调最终还是要回到主线程执行。重计算任务如果放在主线程，页面仍然会卡。

Web Worker 的意义

Web Worker 可以把一部分计算挪到另一个线程：

Worker 不能直接操作 DOM，但适合处理大文件解析、图片压缩、复杂计算。

这就是进程线程基础和前端性能之间的联系。

Node 的单线程误解

Node 的 JavaScript 执行也是单线程，但 Node 底层有线程池处理文件系统、DNS、加密等任务。

所以“Node 是单线程”不能简单理解成“Node 什么都只能一个一个做”。它的事件循环让大量 I/O 任务可以高效处理，但 CPU 密集型任务仍然会阻塞主线程。

小结

进程是资源分配单位，线程是执行单位。多进程更隔离，多线程共享内存但更容易有并发问题。

前端面试问这些，不是让你写操作系统，而是让你理解浏览器、Node、Web Worker、页面卡顿背后的运行模型。知道程序怎么跑，才能更好判断性能问题在哪里。
