HTML 和 CSS 代码风格：团队协作时最容易忽略的基础

2018-10-11
前端基础CSS

写 HTML 和 CSS 不难，难的是团队里很多人长期一起写，还能保持清楚、稳定、好维护。

代码风格规范的价值就在这里。它不是为了限制写法，也不是为了把每个人的习惯磨成一样，而是为了减少沟通成本。一个人写的页面，另一个人接手时，应该能快速看懂结构、样式职责和命名意图。

这类基础规范越早统一，后面越少返工。

HTML 要尽量语义化

HTML 不只是把内容放到页面上。

合适的标签能让页面结构更清楚，也有利于可访问性、SEO 和后期维护。

例如：

  • 页面主标题用 h1
  • 段落用 p
  • 导航用 nav
  • 主要内容用 main
  • 列表内容用 ul、ol、li

不要为了样式方便就到处使用 div。样式应该交给 CSS，结构应该交给合适的 HTML 标签。

图片的 alt 文本经常被忽略。

  • 读屏软件可以读出图片含义
  • 搜索引擎能更好理解内容

  • 属性顺序尽量稳定
  • 不写无用代码

把规范落到检查清单

代码风格不要只停留在口头约定。每次提交前，可以快速过一遍：

  • 页面是否有清楚的标题层级
  • 交互控件是否有可访问名称
  • 图片 alt 是否准确
  • CSS 类名是否表达业务或组件含义
  • 是否存在无用选择器和重复声明
  • 是否有过深嵌套或过强选择器
  • 同类组件的结构和命名是否一致

这些检查不复杂，但能拦住很多后续维护问题。

小结

HTML/CSS 风格规范的核心是可读、可维护、可协作。

语义化标签、清楚命名、稳定格式、必要的可访问性信息，都是前端基础工程质量的一部分。项目越多人维护，这些规则越有价值。

真正好的规范不会让人写得更慢，而是让团队在修改、评审和交接时少猜一点。
