HTML 和 CSS 代码风格：团队协作时最容易忽略的基础

2017-11-13
前端开发

写 HTML 和 CSS 不难，难的是团队里很多人长期一起写，还能保持清楚、稳定、好维护。

代码风格规范的价值就在这里。它不是为了限制写法，而是为了减少沟通成本，让大家看到同一份代码时能快速理解。

HTML 要尽量语义化

HTML 不只是把内容放到页面上。

合适的标签能让页面结构更清楚，也有利于可访问性、SEO 和后期维护。

例如：

  • 页面主标题用 h1
  • 段落用 p
  • 导航用 nav
  • 主要内容用 main
  • 列表内容用 ul、ol、li

不要为了样式方便就到处使用 div。样式应该交给 CSS，结构应该交给合适的 HTML 标签。

图片要写 alt

图片的 alt 文本经常被忽略。

但它很重要：

  • 图片加载失败时可以显示说明
  • 读屏软件可以读出图片含义
  • 搜索引擎能更好理解内容

CSS 最怕命名随意。

保持格式一致

团队代码里最基础的规则包括：

  • 缩进一致
  • 属性顺序尽量稳定
  • 不写无用代码
  • 删除不用的选择器
  • 避免过深嵌套

小结

HTML/CSS 风格规范的核心是可读、可维护、可协作。

语义化标签、清楚命名、稳定格式、必要的可访问性信息，都是前端基础工程质量的一部分。项目越多人维护，这些规则越有价值。
