Vue Router 导航守卫：登录拦截和权限控制别写成一团

2019-09-13
Vue组件与状态

Vue 后台系统里，路由守卫几乎必写。

登录页、首页、权限页、404 页面、菜单页面都绕不开它。面试也常问导航守卫，因为它能看出你是否理解路由流程，而不是只会 this.$router.push。

我做过几个中后台项目，守卫这块踩的坑不算少：刷新白屏、跳转死循环、权限菜单出来了但页面进不去、退出登录后还能看到上一个用户的数据。这些问题十有八九都出在守卫的逻辑没理清。下面这些都是我自己在项目里反复改出来的写法，不是纯背概念。

先说一个容易被忽略的点：Vue Router 的守卫分好几层，从全局到组件依次是 beforeEach、路由独享的 beforeEnter、组件内的 beforeRouteEnter / beforeRouteUpdate / beforeRouteLeave，最后还有全局 afterEach。后台系统里登录和权限基本都压在全局 beforeEach 上，但像“离开未保存的表单要二次确认”这种就更适合放 beforeRouteLeave，别一股脑全塞进全局守卫里。

next 只能明确调用一次

守卫里最常见的 bug 是多个分支都调用 next。

这样会出问题。next() 先放行了，紧接着又 next('/login') 想拦截，Vue Router 实际只认第一次有效调用，后面的会被忽略，但控制台经常会出现奇怪的导航行为，调试时很迷惑。

每个分支都应该 return，让流程清楚结束。我自己的习惯是把守卫写成「要么 next() 放行，要么 next(地址) 重定向，调用完立刻 return」，绝不让一次执行里出现两条都可能跑到的 next。

动态路由

后台系统经常根据权限生成路由。

大致流程：

  1. 登录拿 token
  2. 拉用户信息和权限
  3. 根据权限过滤路由
  4. router.addRoutes
  5. 进入目标页面

动态路由要注意刷新后的恢复。不能只在登录时添加一次，刷新后路由表又回到初始状态。这是后台系统最常见的「刷新白屏」根因：用户在 /admin/xxx 刷新，token 还在，但动态路由还没加回来，to 匹配不到任何路由，于是白屏或者跳 404。

路由错误和接口错误要分开

进入页面失败可能是：

  • 没登录
  • 没权限
  • 路由不存在
  • 用户信息接口失败

不要都跳登录。

401 跳登录，403 去无权限页，404 去不存在页面，接口 500 提示服务异常。错误结构统一后，守卫判断会清楚很多。

我一般在 axios 响应拦截器里统一收口 401，而不是在守卫里到处判断。401 拦截器里直接清 token、跳登录，守卫只管「有没有 token、有没有权限」这两件事，职责分得开，排查也快。

404 也有讲究。动态路由场景下，通配的 { path: '*', component: NotFound } 这条必须在 addRoutes 之后再加，不能跟静态路由一起注册。否则动态路由还没加进来时，所有未匹配的地址都先撞上通配规则跑去 404 了，刷新就会闪一下 404 再跳回来，很难看。

配合 afterEach 做体验细节

beforeEach 管拦截，afterEach 管「进来之后做点什么」，它不接收 next，没法拦截。我常用它做两件事：设置页面标题、关掉顶部进度条。

进度条的 NProgress.start() 放在 beforeEach 开头，done() 放 afterEach，配合下来切页面就有个加载条，长接口等待时用户体验会好不少。

Vue Router 守卫不是简单判断 token。它承担登录拦截、用户信息恢复、权限路由、错误分流这些职责。

面试问守卫，项目里更要写清楚流程。白名单、next 调用、动态路由、接口错误处理都要明确，否则后台系统很容易出现刷新白屏或跳转死循环。
