图片懒加载实践：首屏图千万别懒

2023-07-07
前端基础性能与缓存

图片懒加载是很常见的性能优化。

列表里几十张图，如果一进页面就全部加载，会浪费带宽，也拖慢首屏。懒加载能让首屏以下的图片等快进入视口时再请求。

但懒加载也很容易用错。最典型的错误，是把首屏主图也懒加载了。结果浏览器本来可以早点下载 LCP 图片，却被你延后了，首屏反而更慢。

原生 loading=lazy 够用很多场景

现代浏览器支持：

这对普通文章列表、商品列表、头像墙已经够用。浏览器会根据距离视口的位置决定何时加载。

但它不是精确控制工具。不同浏览器的触发距离和策略不同。如果你需要更细的控制，比如提前 300px 加载、统计曝光、切换占位状态，就要用 IntersectionObserver。

首屏关键图片不要 lazy

首屏 banner、文章头图、商品主图如果是 LCP 候选，不要写 loading="lazy"。

浏览器预加载扫描器能更早发现并下载它。

错误兜底不能忘

图片加载失败很常见：资源被删、CDN 异常、URL 为空、权限过期。

注意避免 fallback 也失败导致死循环。真实项目里可以判断当前是否已经是 fallback。

装饰性图片 alt 为空，内容性图片 alt 要有意义。不要一律写 alt="image"。

懒加载和骨架屏不是一回事

懒加载解决的是“什么时候加载资源”，骨架屏解决的是“加载前展示什么”。

列表图片可以用灰色占位或主色块。不要为了每张小图都做复杂 blur，占位本身也有成本。

首屏大图可以考虑低质量占位，但要注意不要让占位图成为 LCP。真正用户关心的是清晰主图什么时候出来。

我的图片懒加载清单

我会检查：

  • 首屏 LCP 图片没有 lazy
  • 首屏以下图片才懒加载
  • 图片有 width/height 或 aspect-ratio
  • 响应式图片尺寸和下载尺寸匹配
  • 懒加载提前量足够
  • 加载失败有兜底
  • alt 文案符合图片用途

图片懒加载不是无脑加属性。首屏图要快，屏外图要晚，空间要预留，失败要能兜底。做到这几点，收益才稳定。
