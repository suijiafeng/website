Mock.js 联调前的接口模拟：别让页面开发一直等后端

2018-08-11
前端基础构建与模块化

前后端并行开发时，最怕页面写到一半发现接口还没好。

如果所有页面都等后端联调，进度会被卡住。Mock.js 这类工具的价值，就是先按约定数据结构把页面跑起来，等接口完成后再替换真实请求。

但 mock 也有边界。它应该服务开发，不应该变成另一套和后端不一致的接口。

加一点延迟

接口秒回时，loading 状态看不出来。

这样可以测试按钮 loading、骨架屏、重复提交等状态。

不要所有接口都无延迟，否则页面看起来正常，真实环境一慢问题就暴露。

mock 开关要明确，不要让测试环境或生产环境误引入 mock。

小结

Mock.js 能让前端不必一直等接口，但它必须建立在接口约定之上。

字段结构、错误格式、延迟状态、开关方式都要清楚。mock 的目标是提前发现页面问题，不是制造一套和真实后端不一样的世界。
