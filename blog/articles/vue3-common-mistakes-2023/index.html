刚开始用 Vue3 时，最容易踩的几个坑

2023-06-07
Vue前端开发

Vue3 已经很成熟，但从 Vue2 或 Options API 迁移过来时，还是很容易写出一些“能跑但不太对”的代码。

很多坑不是语法不会，而是对组合式 API 和响应式规则理解不够清楚。

基本类型不要直接用 reactive

reactive 适合对象、数组、Map、Set 这类引用类型。

如果是数字、字符串、布尔值，应该使用 ref。

props 不要直接修改

子组件接收的 props 应该当作只读数据。

如果子组件需要修改值，通常有两种方式：

  • 通过 emit 通知父组件修改
  • 在子组件里复制一份本地状态

watch 不要滥用

watch 很有用，但不应该把所有逻辑都塞进去。

如果一个值可以由其他值计算出来，优先考虑 computed。

watch 更适合处理副作用，比如请求接口、写入缓存、同步外部状态。

但不要把所有业务都塞进一个巨大的 usePage。

好的组合式函数应该职责明确，例如只处理请求、表单、分页、弹窗或权限中的一类问题。

小结

Vue3 的核心不是把 data、methods 换成 ref、reactive，而是重新组织组件逻辑。

基本类型用 ref，复杂对象用 reactive；解构时注意响应式；props 保持单向数据流；能用 computed 就不要滥用 watch。这些习惯能减少很多后期维护问题。
