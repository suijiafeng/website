XSS 和 CSRF：前端安全面试题，也是真实项目的底线

2019-08-28
前端基础

前端安全看起来离业务开发很远，但其实很多漏洞都来自普通页面。

评论区显示用户输入、后台富文本、活动页 URL 参数、登录态 Cookie，这些都是安全问题容易出现的地方。面试问 XSS 和 CSRF，不是为了背缩写，而是确认你有没有基本的安全边界意识。

前端不要把敏感 token 随便放到页面变量里。

CSRF 是什么

CSRF 是利用用户登录态，诱导浏览器向目标网站发送请求。

比如用户已经登录了某后台，攻击页面放一个表单自动提交：

如果目标网站只靠 Cookie 判断登录，浏览器会自动带上 Cookie，危险操作可能被执行。

CSRF 防护

常见方式：

  • CSRF Token
  • SameSite Cookie
  • 校验 Referer 或 Origin
  • 重要操作二次确认

服务端校验 token 是否匹配。

GET 不要做危险操作

删除、修改、支付这类操作不要用 GET。

这很危险，因为图片、链接、爬虫都可能触发 GET。

危险操作应该使用 POST、PUT、DELETE，并配合权限和 CSRF 防护。

前端能做什么

前端不能单独解决安全问题，但能做好这些：

  • 不直接渲染不可信 HTML
  • 对用户输入做必要限制
  • 不把敏感信息暴露在页面上
  • 请求层统一带安全 token
  • 对危险操作做确认
  • 接口错误统一处理，不泄露内部信息

安全一定是前后端协作。

小结

XSS 关注脚本注入，CSRF 关注利用登录态发请求。

面试问这两个，是因为它们是 Web 安全基础。项目里最重要的是：外部输入默认不可信，危险操作必须有服务端校验，前端不要把安全当成“后端的事”。
