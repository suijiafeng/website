Node 脚本自动化：把重复操作从人脑里拿出来

2022-09-09
前端基础构建与模块化

前端项目里有很多重复操作。

新增页面要改路由、改菜单、加权限；新增图标要生成索引；发布前要检查环境变量；文档要根据文件生成目录。这些事靠人记，很容易漏。

Node 脚本的价值，就是把重复、机械、容易出错的操作固化下来。

脚本先解决小问题

文件处理要谨慎

写脚本最怕误改文件。

批量写入前，最好先 dry run：

输出要清楚：读了哪些文件，改了哪些文件，跳过哪些文件。脚本不是黑盒，失败时要能定位。

如果处理 JSON，尽量用 JSON.parse/stringify，不要正则硬改。处理 JS/TS 代码时，如果只是简单生成文件可以字符串模板；如果要修改已有代码，最好使用 AST 工具，避免格式和语法被破坏。

我的脚本清单

写 Node 自动化脚本时，我会检查：

  • 是否解决了真实重复操作
  • 是否有 dry run 或清晰输出
  • 是否避免误改无关文件
  • 解析结构化数据时是否使用结构化 API
  • 生成结果是否稳定
  • 远程 API 失败是否中断
  • npm scripts 命名是否清楚
  • CI 是否能复用同一套脚本

自动化不是为了炫技，而是把“记得去做”变成“脚本会检查”。项目越大，这种小脚本越值钱。
