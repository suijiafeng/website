JavaScript 数组常用方法整理：写业务代码时最常用的是哪几个

2020-08-19
前端基础

数组是 JavaScript 里使用频率非常高的数据结构。

无论是列表渲染、接口数据处理、条件筛选，还是状态更新，很多逻辑最后都会落到数组操作上。

我以前学数组方法时，也背过 map、filter、reduce 这些名字。但真正写业务之后才发现，关键不是记住 API，而是看到一段逻辑时能说清楚：我到底是在转换、筛选、查找，还是在产生副作用。

方法选对了，代码会自己变清楚。方法选错了，几行代码也会让人读半天。

map：把一个数组变成另一个数组

map 最适合做转换。

它不会修改原数组，而是返回一个新数组。

这也是它在前端渲染里特别常见的原因，例如把数据列表映射成组件列表。

先处理接口错误，再处理数组

业务里数组通常来自接口。接口失败时，不应该直接假设 data.list 一定存在。

我现在很少在组件里直接写 res.data.list.map(...)。接口结构一变，页面就容易炸。先确认它是数组，再进入数组处理，会稳很多。

写在最后

数组方法的关键不在于记住名字，而在于先想清楚你的意图：

  • 要转换，就用 map
  • 要筛选，就用 filter
  • 要找一个，就用 find
  • 只遍历执行逻辑，就用 forEach

只要意图和方法对上，代码会更清楚，也更不容易写乱。

我现在判断数组代码好不好，不看它用了多少高级方法，而看它能不能让后来的人一眼看懂数据从哪里来、经历了什么变化、找不到或接口失败时会怎样。数组方法只是工具，真正重要的是把业务意图写出来。
