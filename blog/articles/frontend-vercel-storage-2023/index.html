Vercel 推出存储能力后，前端部署不只是静态页面了

2023-05-05
前端开发

以前很多人对 Vercel 的印象是：部署前端页面很方便。

把 Next.js、React 或静态站点推到 GitHub，再连到 Vercel，几分钟就能上线。

但一个真正的 Web 应用通常不只需要页面，还需要数据。

比如用户信息、文章内容、订单记录、图片文件、缓存数据，这些都离不开数据库或存储服务。

前端应用为什么需要存储

静态页面只负责展示，动态应用需要读写数据。

常见需求包括：

  • 博客文章从数据库读取
  • 用户上传头像或附件
  • 商品列表需要分页查询
  • 表单提交后要保存
  • 页面需要缓存热点数据

如果部署平台只负责页面，开发者就要额外找数据库、对象存储、缓存服务，再手动配置连接。

这会让小项目变复杂。

Vercel Postgres 是什么

Vercel Postgres 可以理解为 Vercel 提供的 PostgreSQL 数据库方案。

PostgreSQL 是常见的关系型数据库，适合保存结构化数据，比如用户、文章、商品、订单。

这样前端项目不再只是“展示页面”，而是可以更自然地变成完整应用。

Vercel Blob 适合存文件

数据库适合保存结构化数据，但不适合直接存大文件。

图片、PDF、音频、视频这类内容，更适合放在对象存储里。

Vercel Blob 就是面向文件存储的能力，适合：

  • 用户头像
  • 文章封面
  • 上传附件
  • 富文本图片

通常做法是：文件放到 Blob，数据库里只保存文件地址和元信息。

KV 适合做轻量缓存

有些数据不一定要放进关系型数据库。

例如：

  • 验证码
  • 临时状态
  • 页面访问计数
  • 热门列表缓存
  • 用户会话信息

这类数据更适合用键值存储，也就是 KV。

KV 的特点是读写简单、速度快，但不适合复杂关联查询。

这对前端开发有什么影响

Vercel 增加存储能力后，前端部署平台的边界变宽了。

以前你可能需要组合：

  • Vercel 部署页面
  • 云数据库保存业务数据
  • 对象存储保存文件
  • Redis 保存缓存

现在一部分能力可以在同一平台里完成，尤其适合中小项目、个人项目、原型产品和内容站。

不代表所有项目都该放在 Vercel

平台能力变强，不等于所有业务都适合。

如果项目有复杂权限、重度后台任务、强一致事务、大规模数据分析，仍然要认真评估数据库、服务端架构和运维方案。

Vercel 的优势是让前端应用更快从想法变成可运行产品，但不是替代所有后端架构。

小结

Vercel 的存储能力让前端部署从“上线页面”进一步走向“上线应用”。

Postgres 负责结构化数据，Blob 负责文件，KV 负责轻量缓存。理解它们各自适合什么场景，比盲目追新更重要。
