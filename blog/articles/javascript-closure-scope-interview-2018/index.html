JavaScript 闭包和作用域：面试常问，项目里也经常踩坑

2018-01-17
JavaScript前端基础

闭包是前端面试里绕不开的问题。

刚开始听到这个词时，很容易觉得它像一个专门用来考人的概念。可写项目久了会发现，闭包并不只存在于面试题里。事件回调、定时器、模块封装、私有变量、异步请求，很多地方都在用它。

只是我们平时不一定会把它叫作闭包。

先从作用域说起

JavaScript 里函数会创建自己的作用域：

inner 可以访问 outer 里的 name。这是词法作用域决定的：函数能访问它定义时所在作用域里的变量。

注意是“定义时”，不是“调用时”。

输出是 global。因为 printName 定义在全局作用域，它访问的是全局的 name。

这类题在面试里很常见，目的不是为难人，而是确认你知道 JavaScript 作用域不是动态绑定的。

什么是闭包

如果一个函数离开了它定义时的作用域，仍然能访问那个作用域里的变量，就形成了闭包。

createCounter 执行完了，但 count 没有被释放，因为返回的函数还在引用它。

这就是闭包最常见的用法：保留一份外部访问不到、但内部函数可以继续使用的状态。

外部不能直接改 score，只能通过方法访问。

这种写法在一些组件库、工具模块里很常见。它比全局变量安全，也让状态边界更清楚。

这种写法现在看起来有点老，但在很多老项目里很常见。理解它，接手老代码会轻松很多。

闭包不是越多越好

闭包会让变量生命周期变长。用得好是封装，用不好就是内存占用和难排查状态。

比如：

只要返回函数还在，data 就不会释放。

项目里不要为了“高级”到处写闭包。它应该用在确实需要保存状态、隐藏变量、延迟执行的地方。

小结

闭包的核心并不复杂：函数记住了自己定义时的作用域。

面试问闭包，通常会连着问作用域、循环变量、定时器、私有变量和内存。项目里用闭包，也要记住它的代价：变量不会因为外层函数执行结束就一定释放。

理解闭包以后，再看事件回调、模块封装和异步代码，会清楚很多。
