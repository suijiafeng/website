CSS 半透明边框：rgba、hsla 和 background-clip

2018-03-19
前端基础CSS

CSS 中做半透明颜色，最常见的是 rgba() 和 hsla()。

它们都可以用来设置半透明背景、文字或边框。

但做半透明边框时，有一个细节很容易被忽略：元素背景默认会延伸到边框区域下面。

所以你看到的半透明边框，有时不是“边框透出了外层背景”，而是“边框下面仍然压着元素自己的背景”。理解这一点，才能把效果调对。

我第一次认真做这个效果，是给一个深色背景的弹窗加一圈“磨砂玻璃”的浅色描边。设计稿上边框是若隐若现的白色，能透出后面模糊的背景。我照着写了 border: 1px solid rgba(255,255,255,0.3)，结果边框看着就是实打实的浅灰，一点透的感觉都没有。盯着调了半天透明度，从 0.3 调到 0.1 都不对——其实问题根本不在颜色，而在背景把边框区域盖住了。这个坑没踩过真想不到，踩过一次就刻进 DNA 了。

这里有个判断小技巧：如果你的边框颜色和背景色色系接近（比如白底配半透明白边框、白底配半透明黑边框），那大概率会受背景铺底影响，得格外留意；如果边框颜色和背景反差很大，背景压在下面也未必那么明显。但无论如何，养成“想透出外层就管好 background-clip”的习惯总没错。

另外提一句 rgba 的简写。2018 年我们基本还是写完整的 rgba(0,0,0,0.2)，那种 rgb(0 0 0 / 20%) 的新语法浏览器支持还不全，生产环境我不敢用，老老实实四个参数最稳。

我做主题色衍生的时候特别依赖这点。比如一个按钮，正常态、hover、focus、disabled 想保持同一个蓝色色相，只动亮度和透明度，用 hsla 一眼就能看出每个状态改了哪个轴：hsla(210, 90%, 50%, 1) 是实色，hsla(210, 90%, 50%, 0.24) 是它的浅色边框，hsla(210, 90%, 60%, 1) 是亮一点的 hover。换成 rgba 这一组数字之间毫无规律可言，改起来全靠试。所以我的习惯是：纯展示的固定色用 rgba 无所谓，但只要涉及“一个色相的一族状态”，就上 hsla。

为什么需要 background-clip

有时你会发现，半透明边框效果并不明显。

原因是元素背景默认会绘制到边框下面。

如果背景是白色，边框半透明后看到的也是下面的白色背景，看起来就像边框变浅了，而不是透出外层背景。

border-radius 和 background-clip 经常一起出现。否则圆角区域的背景和边框可能看起来不够干净。

补充几个 background-clip 的实战细节。它有三个值：border-box（默认，铺到边框外缘）、padding-box（铺到内边距，不进边框）、content-box（只铺内容区）。做透明边框用 padding-box 就对了。

但 padding-box 配 background-clip: text 完全是两码事，别搞混——text 那个是把背景裁进文字里做渐变文字的，和边框无关。

还有个容易忽略的交互：如果元素同时有 box-shadow 的 inset 阴影，或者背景是图片，切到 padding-box 后阴影/图片的可见范围也会跟着变，调的时候要一起看效果，别只盯着边框。我有次切了 padding-box 之后发现内阴影边缘怪怪的，就是这个原因。

兼容性方面，background-clip: padding-box 在 2018 年主流浏览器都没问题，IE9 以上也支持，可以放心用。

用双背景做渐变边框

如果想要透明或渐变边框，也可以使用多层背景。

第一层背景负责内容区域，第二层背景负责边框区域。因为边框本身是透明的，所以底下的渐变会露出来。

这类写法适合强调状态，但不要滥用。所有卡片都加渐变边框，页面会很快变得嘈杂。

这套双背景的原理值得多嚼一下：一个元素可以叠多层背景，逗号分隔，先写的在上层。linear-gradient(#fff,#fff) padding-box 是一层纯白、只铺到内边距区域；linear-gradient(...) border-box 是渐变层、铺到边框外缘。因为 border 本身设了 transparent，所以底下那层渐变就从透明的边框里露出来了，视觉上就成了一圈渐变描边。

为什么不直接用 border-image 做渐变边框？我也试过，border-image 配渐变是能做，但它和 border-radius 合不来——圆角直接失效，边框会变成直角，这是它的硬伤。双背景这招的最大好处就是圆角能正常保留。代价是 border 区域被背景接管了，如果你还想给边框本身做别的样式（比如虚线），就没法兼顾，得另想办法。

实际项目里我用双背景渐变边框，多半是给“选中的套餐卡片”“高亮的推荐项”这种少量、需要抓眼球的元素。普通列表卡片老老实实一条实线边框就够了，渐变边框用多了反而廉价。

适合哪些场景

半透明边框适合：

  • 弹窗边缘
  • 卡片外框
  • 图片遮罩
  • 深色背景上的浮层
  • 毛玻璃风格里的边界线

但要注意对比度，不要让边框太淡，影响用户识别区域边界。

有交互状态时，也要确保 hover、focus、disabled 都能被看出来：

半透明不是为了“更淡”，而是为了和背景建立层次。

关于对比度我多嘴一句。半透明边框最大的风险是“淡到看不见”。在毛玻璃、深色遮罩这类背景上，边框透明度低一点没问题；但放到内容复杂、背景花的地方，太淡的边框等于没有，用户分不清区域边界。我的经验是：边框的作用如果是“装饰性的高光”，可以很淡；如果它承担着“区分这块是个独立卡片/可点击区域”的职责，那透明度别低于 0.3 左右，宁可实一点也别让人找不着边。无障碍那边对非文本元素也是有对比度建议的，区域边界这种功能性的线条，别为了好看牺牲可辨识度。

半透明边框看似小技巧，关键在于背景是否盖住了边框。rgba/hsla 能表达颜色与透明度，background-clip 决定背景是否延伸到边框下。先想清楚边框要透出的对象，再选策略：简单场景用 background-clip: padding-box，要渐变就用双背景。把这些点照顾好，效果既美观又可靠。
