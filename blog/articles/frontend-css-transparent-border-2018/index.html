CSS 半透明边框：为什么 `rgba` 画出来总像发灰的实线

2018-03-19
前端基础CSS

半透明边框最容易出现的错觉，是你把颜色透明度调低了，就以为“透”的感觉自然也出来了。实际一上页面，经常看到的只是发灰的一圈实色，离设计稿里那种能透出背景的边缘差得很远。

这次弹窗边框就是这样。设计稿上是一圈若隐若现的白色描边，像磨砂玻璃边缘，能隐约透出后面深色背景；我最开始写出来的，却只是浅灰色的厚边框：

我自己看着觉得差不多——不就是个浅色边框吗。但她把设计稿和页面并排一放，差距确实明显：稿子上的边框是"浅浅的一层白纱盖在深色背景上"，我的页面上边框就是一圈实打实的浅灰，一点"透"的感觉都没有。她撂下一句"改完叫我"，我就对着这个弹窗开始一处一处试。

第一轮：调透明度，越调越不对

我的第一反应是透明度不够低。0.45 改 0.3，不对；0.3 改 0.2、0.1，边框越来越淡，但淡的方向不对——它在往"白"里淡，不是往"深色背景"里透。到 0.1 的时候边框几乎看不见了，可看得见的部分依然是灰白色，跟遮罩的深蓝色一点关系没有。

先把 rgba() 本身交代清楚，它没有任何问题：

rgba() 的四个参数拆开说：

  • 前三个值是红、绿、蓝，0~255；
  • 第四个值是透明度；
  • 0 表示完全透明；
  • 1 表示完全不透明。

rgba(0, 0, 0, 0.2) 就是 20% 不透明度的黑色。外层背景是浅灰时，这样的边框会比较自然：

顺带一提，现在（2018 年初）规范里已经有 rgb(0 0 0 / 20%) 这种空格斜杠的新语法了，但浏览器支持还不全，生产环境我不敢用，老老实实写四个参数最稳。另外八位十六进制 #RRGGBBAA（比如 #ffffff73）各大新版浏览器也陆陆续续支持了，可我们还背着 IE11 的兼容指标，同样只能看看。

预处理器这边倒是能提前补一点体验。项目里用的是 Sass，rgba() 函数它原生支持透传，但更好用的是 transparentize() 和 rgba($color, $alpha) 这类颜色函数——已经定义好的变量色值，想单独派生出一个半透明版本，不用把三个 RGB 分量重新抄一遍，减少了改一处忘一处的风险。这跟 hsla() 解决的是同一类问题：都是想在写颜色的时候少关心几个跟当前目的无关的参数。

透明度语义都对，那问题出在哪？我盯着那圈"灰白"忽然反应过来一件事：半透明的白色边框，透出来的应该是它"下面"的东西——那它下面到底是什么？

边框下面压着的是我自己的背景

打开 DevTools，给 .dialog 临时加了一句 background: transparent，边框瞬间就"透"了，深色遮罩从边框里渗出来，跟设计稿一模一样。

真相就是这一条：**元素的背景默认会一直延伸到边框区域下面。**我以为半透明边框透出的是外层的深色遮罩，实际上边框底下先压着的是弹窗自己的白色背景。半透明白边框叠在白背景上，怎么调都是白，透明度只决定"多白"，永远透不出外面的深色。

所以之前看到的半透明边框效果，有时根本不是"边框透出了外层背景"，而是"边框下面仍然压着元素自己的背景"。理解这一点，才能把效果调对。

这里有个判断小技巧：如果边框颜色和元素背景色系接近（白底配半透明白、白底配半透明黑），铺底的影响会非常明显，必须警惕；边框和背景反差大时，铺底未必看得出来——这也是为什么这个坑平时藏得住，一到设计师较真的稿子上就现形。

background-clip：让背景别铺到边框底下

背景铺到哪里，是有属性管的——background-clip。它有三个值：

  • border-box：默认值，背景一直铺到边框外缘，前面那圈发灰的边框根源就在这（浏览器默认值一直是它）；
  • padding-box：背景只铺到内边距区域，不进边框；
  • content-box：只铺内容区，连 padding 都不铺。

做透明边框，答案就是 padding-box：

刷新页面的那一刻确实有点成就感：那圈"白纱"出来了，圆角处也干净——border-radius 和 background-clip 经常要一起出现，不然圆角区域的背景可能从边框缝里露出来，看着很脏。

补几个当晚顺手验证的细节。一是别把 background-clip: padding-box 和 background-clip: text 搞混，text 是把背景裁进文字里做渐变文字用的，跟边框完全两码事。二是它和别的属性有交互：元素同时有 inset 的 box-shadow、或者背景是图片时，切到 padding-box 后阴影和图片的可见范围会跟着变——我切完发现内阴影边缘怪怪的，就是这个原因，调的时候要整体看效果。三是兼容性可以放心：background-clip: padding-box 主流浏览器全支持，IE9 以上也没问题，不用加前缀。

还有一处容易漏看的地方是 box-sizing。这批组件我们全站统一用的是 box-sizing: border-box，边框和内边距都算进 width 里，量出来的尺寸和设计稿对得上；如果哪个老页面漏了这条全局设置、还停在默认的 content-box，边框一改粗细，元素的实际占位就跟着变，稿子上明明是固定宽度的卡片，加了粗边框之后却撑宽了一截，这类问题跟今天讲的背景铺底不是一回事，但经常在同一批稿子的走查里一起冒出来，都得留意。

border 简写的参数顺序也顺手确认了一遍：宽度、样式、颜色三段谁先谁后其实不敏感，border: 12px solid rgba(255, 255, 255, 0.45) 和颠倒顺序写效果一样，浏览器是按值的类型去识别，不是按位置。真正容易出错的地方是漏写 border-style——只写宽度和颜色，边框会整个不显示，这个坑我见新同事踩过，报错都没有，页面上就是干干净净地少了一圈线，查起来比想象中费时间。

第二关：一组蓝色状态边框，rgba 改到眼花

弹窗过了，同一批稿子里还有个上传组件，虚线边框，蓝色系，正常、聚焦、禁用三个状态深浅不同。我先用 rgba 写：

功能没问题，但设计师说聚焦态"蓝得不对，想再亮一点点、不要更深"。用 rgba 调"亮一点点"是很痛苦的——三个通道得一起动，22, 119, 255 改成多少才是"同一个蓝但亮一点"？全靠试。

这种时候就该换 hsla() 了。它的四个参数是色相（H）、饱和度（S）、亮度（L）、透明度（A）：

**hsla 的优势在于"同一个色相下的一族状态"：色相锁死，只动亮度和透明度两个轴。**改完之后我的按钮态是这样一族：

设计师说"再亮一点点"，我把 L 从 50% 拨到 55%，两轮就定稿了。换成 rgba，这组数字之间毫无规律可言。所以我的习惯是：纯展示的固定色用 rgba 无所谓，只要涉及一个色相衍生多个状态，就上 hsla。

顺带辨析一个容易和透明度混的属性：opacity。它调的是整个元素（含子元素、文字、边框）的透明度，而 rgba/hsla 的 alpha 通道只作用在你写透明度的那一层颜色上。上传组件如果直接给整个 .upload-box 设 opacity: 0.5，里面的文字说明和图标会跟着一起变淡，这在禁用态或许是想要的效果，但正常态绝对不能这么图省事——用户会以为整个控件是灰的、不能点。这也是当初调蓝色状态边框时特意用 rgba/hsla 单独控制边框和背景颜色、而不是笼统地拉一个 opacity 的原因。

第三关：稿子上还有一张渐变描边的卡片

真正难的在最后。稿子里有一张"推荐套餐"卡片，边框是一道从蓝到紫的渐变，还带圆角。我第一反应是 border-image：

渐变是出来了，圆角没了——border-image 和 border-radius 合不来，圆角直接失效，边框变成生硬的直角，这是它的硬伤。稿子上明明是圆角，这条路走不通。

最后用的是双背景的招，正好是 background-clip 知识的进阶版：

原理值得嚼一下：一个元素可以叠多层背景，逗号分隔，先写的在上层，而且每层可以单独指定自己的 clip 范围。第一层 linear-gradient(#fff, #fff) 是一块纯白"补丁"，只铺到 padding-box；第二层渐变铺满 border-box。边框本身设成 transparent，于是下层渐变就从透明的边框区域露出来，视觉上就是一圈渐变描边——而且圆角完好，因为这全程是背景在干活，border-radius 照常裁切背景。

这里 border: 1px solid transparent 里的 1px 不能省。边框宽度决定了下层渐变露出来的那圈有多粗，写成 0 的话，border-box 和 padding-box 两个裁切范围完全重合，渐变直接被纯白补丁盖得一点不剩，页面上只剩一张普通白卡片，什么效果都看不出来，调这一版的时候我为这个空白卡片愣了几秒才想明白。

代价也要知道：border 区域被背景接管了，想再给边框本身做别的样式（比如虚线）就没法兼顾。而且这招视觉冲击强，只适合"选中的套餐""高亮推荐项"这种少量抓眼球的元素，所有卡片都上渐变边框，页面很快就嘈杂廉价了。

顺路捡到的两个替代方案

折腾 border-image 失败的过程里，我还试了两条路，虽然这次没用上，记下来备用。

一是 box-shadow 模拟边框。不模糊、只给扩散半径，就是一圈"假边框"：

它的特点是不占布局空间——真 border 会把元素撑大 2px，box-shadow 不会。hover 时想加一圈高亮又不想让元素跳动，这招比切换 border 稳得多。缺点是做不了虚线，也吃不到 background-clip 那套透出逻辑，而且叠多层 box-shadow 时层级顺序和 background 的多层规则正好相反——后写的在下层，跟 background 先写的在上层容易搞混，调的时候得多留意。

二是 outline。它也画一圈线、也不占布局，但 2018 年的 outline 不跟随 border-radius（圆角元素上画出来还是直角框），位置也没法像 border 一样精细控制，所以我基本只把它留给键盘焦点指示用，不拿来做视觉描边——反过来说，用 box-shadow 或 border 做了自定义焦点样式，别忘了被你 outline: none 干掉的可访问性得补回来。

顺手记一个跟颜色值本身相关的小技巧：border-color 可以用 currentColor 取文字颜色，图标按钮或者纯边框按钮想让边框跟着文字色走，不用另外声明一遍颜色值，改一处文字色边框就跟着变，配色调整时能省不少重复劳动。四条边的颜色也可以分开写，border-color: #1677ff #722ed1 #52c41a #faad14 按上右下左的顺序各给一个色，我在那次调状态边框时试过用它做一个四色渐变的土办法，效果比不上真正的渐变描边细腻，但胜在浏览器支持早、写法简单，临时应急够用。

另外还有个反向技巧：透明边框本身也能干活。小图标按钮点击区域太小，加一圈 border: 8px solid transparent 配 background-clip: padding-box，视觉不变、热区变大，移动端上很实用。这招还有个变体我在做三角形箭头指示器时顺手用过：四条边都设透明、只留一条边给颜色，再把宽高压缩到 0，就能拼出一个纯 CSS 三角形，配合 position: absolute 常拿来做下拉菜单或气泡卡片的小尖角，不用额外切图。

这套东西适合用在哪

走查完我把这轮学到的招对照了一遍适用场景：弹窗边缘（就是这次的主角）、卡片外框、图片遮罩的分界、深色背景上的浮层、毛玻璃风格里的边界线，这几处都用得上。共同点是：这些场景里边框的职责是"和背景建立层次"，背景本身有内容、有深浅，边框透一点，元素就像"浮"在背景上而不是"贴"在上面。反过来，纯白底上的普通表格、表单，背景平平无奇，透明边框透出来的还是白，用了等于没用，直接一条实线更省事。

周一验收

今天上午设计师二次走查。弹窗的白纱边框、上传框的三个状态、渐变描边的推荐卡片，一次过。她问我上周五那版是怎么回事，我说边框底下压着自己的背景，她"哦"了一声表示没听懂，但稿子还原了就行。

半透明边框调不出"透"的感觉，第一件事不是调透明度，是问"边框底下是什么"——背景默认铺到 border-box，想透出外层就 background-clip: padding-box。颜色工具按需选：固定色用 rgba 够用，一个色相衍生一族状态就换 hsla，锁色相、拨亮度；新语法和八位 hex 编码再等等浏览器兼容跟上。渐变圆角边框用双背景，border-image 过不了圆角这关；不占布局的描边找 box-shadow。

最后一条是关于"度"的：半透明不是为了更淡，而是为了和背景建立层次。装饰性的高光可以很淡；但边框如果承担着"区分这是个独立卡片、可点击区域"的职责，透明度别低于 0.3 左右——在内容复杂的花背景上，太淡的边框等于没有。无障碍规范对非文本元素也有对比度建议，功能性的线条，别为了好看牺牲可辨识度。宁可被设计师说"实了一点"，也别让用户找不着边。

这次顺手也把这批组件的样式全过了一遍浏览器矩阵：Chrome、Firefox 表现一致，Safari 桌面版没问题，唯独公司内网还留着几台跑 IE11 的验收机器，background-clip: padding-box 在那上面倒是好好的，反而是页面里另一处用了 CSS 变量定义颜色值的地方直接失效——IE11 从头到尾不认 var()，这批组件的颜色值我们仍然是老老实实写死在每条规则里，等哪天验收指标松绑再考虑收拢成变量。
