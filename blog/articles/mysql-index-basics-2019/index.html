MySQL 索引基础：为什么加了索引，查询还是可能慢

2019-04-11
数据可视化与存储

前端虽然不直接写很多 SQL，但接口慢时，经常会听后端说“查库慢”“索引没走”。

面试里也常问索引。即使主要做前端，懂一点数据库索引，对理解接口性能、分页慢、搜索慢都有帮助。

索引是什么

索引可以理解为数据库为了快速查找数据建立的目录。

如果 email 上有索引，数据库可以更快定位到对应记录。

为什么常说 B+ 树

MySQL InnoDB 常用 B+ 树索引。

B+ 树适合范围查询，也能保持较低的树高。数据量很大时，查询仍然能通过较少次数的磁盘读取定位。

不需要把树结构画得很复杂，但要知道：索引不是哈希表那么简单，它既支持等值查询，也支持范围查询和排序优化。

主键索引和二级索引

InnoDB 表数据按主键索引组织。

主键索引叶子节点存整行数据。

索引不是越多越好

索引会提升查询，但会增加写入成本。

插入、更新、删除数据时，索引也要维护。索引太多，写入会变慢，占用空间也会变大。

所以索引要围绕真实查询场景设计。

小结

索引是数据库查询性能的基础，但不是加了就一定快。
