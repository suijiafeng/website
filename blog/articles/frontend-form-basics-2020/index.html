HTML 表单基础回顾：前端交互实际开发中就是从这里开始的

2020-06-06
前端基础

我以前有段时间挺轻视表单，觉得不就是几个输入框、一个提交按钮，样式调好、接口调通就完事。

后来接连踩了几次坑：登录页按回车没反应，因为只绑了按钮 click；资料编辑页没有 name，浏览器自动填充全失效；后台配置表单提交慢，用户连点两次，库里多了两条一样的数据。表单看起来基础，但登录、注册、搜索、下单、资料修改，几乎所有真正和用户打交道的地方都绕不开它。

所以我现在看表单，不会只看“页面有没有做出来”。我会先看用户怎么输入、系统怎么校验、失败怎么提示、提交时怎么防重复、服务端错误怎么落回字段上。

表单的核心作用

表单说到底是在收集用户输入。

这看起来简单，但一旦进入真实业务，就会涉及：

  • 文本输入
  • 单选、多选
  • 下拉选择
  • 校验
  • 提交

所以表单其实是用户和系统之间非常关键的一个桥梁。

常见表单元素

最常用的通常包括：

  • input
  • textarea
  • select
  • button

其中 input 又有多种类型，例如：

  • text
  • password
  • checkbox
  • radio

不同类型对应不同输入场景。

前端校验和表单体验

真实开发里，表单体验很大程度取决于：

  • 提示是否清楚
  • 错误信息是否及时
  • 输入控件是否易用

所以表单不只是“能填进去”，而是要让用户明白自己该怎么填、哪里填错了。

不要破坏原生能力

很多自定义表单组件为了视觉效果，会不小心破坏原生能力，比如：

  • 用 div 假装按钮
  • 用 span 假装 checkbox
  • 输入框没有 name
  • 只监听 click 不监听 submit
  • 错误提示没有和字段关联

这些问题短期看不明显，但会影响键盘操作、自动填充、可访问性和真实提交行为。

视觉可以自定义，但语义最好保留。

我现在写表单，最怕的不是字段多，而是基础能力被自己破坏掉。

form、label、name、submit 这些东西看着老，但它们帮你兜住了键盘提交、自动填充、可访问性和默认语义。复杂表单当然要封装组件、接校验库、做状态管理，可这些都应该建在原生能力之上，而不是把原生能力拆掉以后再自己造一遍。

表单越基础，越容易被随手写坏。认真处理语义、校验、错误反馈、提交状态和服务端失败，比把输入框摆整齐重要得多。
