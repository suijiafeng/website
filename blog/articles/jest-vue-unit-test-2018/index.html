Vue 组件单元测试：先测行为，不要一上来测实现

2018-06-02
Vue构建与模块化

给 Vue 项目补单元测试时，很多人第一反应是：组件这么多，要测到什么时候？

其实不必一开始就覆盖所有组件。测试最应该先保护那些稳定、关键、容易出错的逻辑。尤其是工具函数、权限判断、请求错误转换、复杂表单校验，这些地方比纯展示组件更值得测。

工具函数最适合先测

测试：

这类测试简单、稳定、价值高。项目里金额、日期、权限、参数处理都适合这样测。

组件测试关注用户行为

不要测试组件内部变量叫啥，而要测试用户能看到什么。

如果以后组件内部从 data 改成 Vuex，只要用户行为不变，测试就不应该失败。

异步更新要等 nextTick

Vue DOM 更新是异步的。触发事件后马上断言，经常会失败。

异步测试要写清楚等待点，否则用例会变得不稳定。

请求错误转换值得测

统一错误处理是项目质量的基础。

一旦错误结构统一，页面提示和日志上报都会更稳定。

不要滥用快照

快照测试看起来省事：

但大组件快照很容易变成一大坨 HTML。失败时很难判断是正常变化还是问题。

我只在非常稳定的小组件里用快照。大部分时候，明确断言文本、按钮状态、事件触发更好。

小结

Vue 单元测试不用一开始追求覆盖率。先测工具函数、业务规则、错误处理和关键组件行为。

好的测试应该保护行为，不绑死实现。它不是为了让报表好看，而是在重构时告诉你哪里被破坏了。
