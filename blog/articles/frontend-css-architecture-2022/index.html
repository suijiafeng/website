CSS 架构实践：样式也需要边界

2022-08-12
CSS前端基础构建与模块化

CSS 写乱的速度很快。

刚开始几个页面，随手写 class 没问题。项目大了以后，全局选择器互相影响，组件样式被业务页面覆盖，颜色和间距到处散落，最后改一个按钮能影响三个页面。

CSS 架构不是为了显得高级，而是为了让样式有边界。

全局样式只放真正全局的东西

全局 CSS 应该少。

适合放全局：

  • reset / normalize
  • 字体
  • CSS 变量
  • body 背景和基础文字
  • 通用动画 token

不适合放全局：

  • 某个页面的布局
  • 某个组件的按钮样式
  • 宽泛的 .title、.card

如果必须覆盖，范围要窄，原因要明确。不要写影响全站的 .el-button。

不要用 !important 管理优先级

!important 一旦多了，样式优先级会失控。

它适合少数场景，比如覆盖第三方内联样式或工具类，但不应该成为日常手段。

遇到样式不生效，先查：

  • 选择器是否命中
  • 加载顺序
  • specificity
  • scoped / module 是否影响
  • 是否被状态类覆盖

不要第一反应就是加 !important。

我的 CSS 清单

我会检查：

  • 全局样式是否足够少
  • 组件样式是否跟组件走
  • 类名是否有上下文
  • 颜色、间距是否使用变量
  • 第三方组件覆盖是否集中
  • 是否有大量 !important
  • 页面样式是否会影响其他页面

CSS 的难点不是写出某个效果，而是效果在项目变大后仍然可控。边界清楚，样式才不会变成隐形债务。
