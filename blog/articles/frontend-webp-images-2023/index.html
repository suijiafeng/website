前端 WebP 图片使用入门：让图片更小，页面更快

2023-09-15
前端开发性能优化

图片通常是网页里最占体积的资源之一。

如果一个页面里有很多商品图、封面图或内容配图，图片太大就会直接影响加载速度。用户打开页面时，需要等待更多流量下载完成，体验自然会变差。

WebP 就是为了解决这类问题而常用的一种图片格式。

WebP 是什么

WebP 是 Google 推出的一种图片格式。

它的特点很直接：在保证图片观感接近的情况下，文件体积通常可以比 JPG、PNG 更小。

对前端来说，这意味着：

  • 页面加载更快
  • 图片占用带宽更少
  • 移动端访问更省流量
  • 图片很多的页面更容易优化

所以在电商、博客、资讯站、后台系统封面图等场景里，WebP 都很常见。

为什么不能只放 WebP

WebP 已经被大多数现代浏览器支持，但实际项目里仍然要考虑兼容性。

如果只写一个 WebP 图片地址，遇到不支持 WebP 的浏览器时，图片可能无法正常显示。

更稳妥的做法是：优先提供 WebP，同时准备一张 JPG 或 PNG 作为兜底。

用 JavaScript 判断是否支持 WebP

有些场景里，图片地址不是直接写在 HTML 中，而是由 JavaScript 动态生成。

这时可以先测试浏览器是否能加载 WebP，再决定使用哪一种图片。

如果只是普通页面展示，优先用 picture 就够了。只有在图片地址需要通过脚本动态处理时，才更适合使用这种判断方式。

使用 WebP 时要注意什么

WebP 很有用，但不是所有问题都靠它解决。

实际项目里还要注意：

  • 不要上传超大原图后只依赖浏览器缩放
  • 列表图、缩略图、大图应该使用不同尺寸
  • 图片要设置合理的 alt 文本
  • 首屏图片可以配合懒加载策略优化
  • 重要图片要保留 JPG 或 PNG 兜底

图片优化通常是组合拳。格式只是其中一部分，尺寸、加载时机、缓存策略也同样重要。

小结

WebP 的价值可以简单理解为：让图片更小，让页面更快。

在普通页面中，推荐使用 picture 标签优先加载 WebP，并提供 JPG 或 PNG 兜底。动态图片场景可以用 JavaScript 判断浏览器是否支持 WebP。需要在浏览器里转换图片时，可以借助 canvas 完成。

只要把兼容和兜底处理好，WebP 就是前端图片性能优化里非常实用的一步。
