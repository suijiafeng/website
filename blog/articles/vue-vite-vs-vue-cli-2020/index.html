Vue CLI 和 Vite 该怎么看：一个成熟稳，一个轻快直接

2020-09-12
Vue构建与模块化

Vite 出来之后，Vue 开发者很自然会拿它和 Vue CLI 比。

这两者表面上都能帮你起一个项目、跑开发环境、做打包，但用起来的感觉并不一样。

我一开始也很容易把它们放在“新工具打旧工具”的框架里看。后来真做项目选择时，反而觉得这种看法太粗糙。Vue CLI 和 Vite 背后代表的是两种工程取向：一个成熟、完整、历史包袱也更多；一个轻快、直接，但早期也需要你接受生态还在变化。

Vue CLI 的强项是成熟

Vue CLI 已经陪很多项目跑了很久。

它的优点很明确：

  • 上手路径清楚
  • Webpack 能力完整
  • 插件和配置体系成熟

如果你在一个比较传统、稳定、历史包袱多的项目里，Vue CLI 仍然很靠谱。

它的靠谱不只是“能跑”。很多公司内部项目已经围绕 Vue CLI 建好了脚手架、环境变量、代理、打包分析、部署脚本、权限模板。对这种项目来说，工具链稳定本身就是生产力。

我不会轻易对一个运行良好的老项目说“赶紧换 Vite”。如果团队每周都在交付业务，构建慢还没到影响效率的程度，强行迁移可能只是把可控问题变成未知风险。

Vite 的吸引力在体验

Vite 最容易让人有感知的地方，就是开发阶段反馈更快。

你甚至不需要先把一堆原理吃透，光是启动和热更新速度，已经足够让人愿意试。

这种快不是心理安慰。前端开发里，反馈速度会直接影响人的思路。改一行样式等几秒，和几乎立刻看到结果，写代码的节奏完全不同。

尤其是中大型 Vue 项目，开发服务器启动慢、热更新慢，会让人越来越不愿意做小步调整。Vite 在这点上的吸引力非常真实。

但我也会提醒自己：开发体验快，不等于整个工程自动变简单。生产构建、浏览器兼容、插件能力、团队已有流程，都要一起看。

这不是淘汰关系

在 2020 这个时间点，更合理的理解不是“谁干掉谁”，而是：

  • Vue CLI 代表成熟的 Webpack 工具链
  • Vite 代表一种更轻、更快的新方向

我会按项目类型做判断。

如果是新项目，尤其是团队愿意接受新工具链，我会优先认真考虑 Vite。它带来的开发体验收益很直接，配置也更轻。

如果是老项目，尤其是 Webpack 配置深、插件多、部署链路复杂，我会先评估迁移成本，而不是为了“技术先进”立刻动手。

我会怎么选

我的判断大概是这样：

工具链选择不是投票选阵营，而是看项目阶段。

差异不只在启动速度

Vue CLI 基于 Webpack，很多能力来自成熟的 loader 和 plugin 体系。你几乎能找到各种历史问题的解决方案。

Vite 的开发阶段基于原生 ESM，很多反馈更快，配置也更直接。但这也意味着一些 Webpack 时代的习惯不能原样照搬。

写在最后

如果你现在手上项目跑得稳，没必要为了新就立刻重构全部工具链；但如果你正在起新项目，Vite 已经足够值得认真看一眼。

它带来的不是小修小补，而是开发体验上的一条新路。

我现在看 Vue CLI 和 Vite，不会简单说谁更好。Vue CLI 像一套成熟的老工地体系，重一点，但很多问题有答案；Vite 像一条更轻的新路，走起来快，但你要确认团队知道路怎么修。

选工具不是表态，选的是你愿意承担哪一类成本。
