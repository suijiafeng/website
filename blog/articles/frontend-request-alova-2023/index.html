前端请求库不只是发请求：从 Axios 到 Alova 的思路变化

2023-05-04
前端开发VueReact

很长一段时间里，前端发请求最常见的选择是 Axios。

它解决了 XMLHttpRequest 写起来麻烦的问题，也提供了拦截器、请求配置、响应处理等能力。

但今天的前端请求，已经不只是“把接口调通”。

请求背后还有很多状态

一个普通列表请求，通常不只包含接口调用。

页面还要处理：

  • 加载中
  • 请求失败
  • 空数据
  • 分页
  • 缓存
  • 重试
  • 取消请求
  • 乐观更新

如果这些状态都由业务页面自己写，代码很快会变重复。

Axios 更像基础 HTTP 客户端

Axios 的定位比较清楚：发请求、收响应、处理拦截。

它本身不会深度管理 Vue 或 React 的响应式状态。

所以在组件里经常会看到：

然后每个页面都写一遍请求前、请求成功、请求失败、请求结束。

Alova 这类库关注请求策略

Alova 这类现代请求库更关注“请求策略”。

也就是说，它不只是发出 HTTP 请求，还希望帮你处理请求相关状态。

例如：

  • 自动维护 loading
  • 自动维护 error
  • 提供分页请求策略
  • 支持缓存和失效
  • 和 Vue、React 等框架集成

这类思路和 TanStack Query、SWR 等工具有相似之处：把请求当成应用状态的一部分来管理。

什么时候需要换请求方案

如果项目只是少量接口，Axios 或原生 fetch 完全够用。

但如果项目里有大量列表、搜索、分页、缓存、重复请求和状态同步，继续手写请求状态会越来越累。

这时可以考虑引入请求状态管理工具，而不是只封装一个 request 函数。

小结

前端请求库的发展方向，已经从“更方便地发请求”变成“更稳定地管理请求状态”。

Axios 仍然适合基础 HTTP 能力；Alova 这类工具则更适合请求状态复杂、页面数量多的项目。选型时要看业务复杂度，而不是只看库名流行不流行。
