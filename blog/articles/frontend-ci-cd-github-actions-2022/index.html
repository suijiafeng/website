前端 CI/CD 实践：用 GitHub Actions 把构建和部署变成流水线

2022-08-16
构建与模块化前端基础

很多前端项目早期发布都很手工：本地跑一下 build，确认没报错，然后把 dist 上传到服务器。项目小的时候还能接受，但团队协作后，这种方式很容易出问题。

有人忘了跑 lint，有人用错 Node 版本，有人本地依赖和线上不一致，有人把未构建的代码发了出去。CI/CD 的价值就是把这些容易漏掉的步骤固定成流水线。

GitHub Actions 已经足够成熟，用它给前端项目搭建基础流水线成本不高。

CI 先解决质量门禁

CI 的第一目标不是部署，而是确保代码合并前经过统一检查。

基础步骤通常包括：

  • 安装依赖
  • 运行 lint
  • 运行测试
  • 运行 build

但缓存只是优化，不应该影响正确性。流水线应该在没有缓存时也能完整跑通。

如果遇到奇怪问题，第一步可以清缓存或临时关闭缓存确认。不要把缓存当成构建产物管理工具。

  • production

小结

前端 CI/CD 的核心价值，是把质量检查和发布步骤标准化。每个人本地环境不同没关系，最终都要经过同一条流水线。

一个合格的前端流水线至少应该固定 Node 版本，使用 lockfile 安装依赖，运行 lint、test、build，区分部署环境，保护密钥，并记录发布版本。做到这些，项目发布会从“靠人记得”变成“靠流程保证”。
