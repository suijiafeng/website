CSS 布局排查方法：别只靠改到看起来对

2023-06-09
CSS前端基础

CSS 布局问题最容易让人烦躁。

明明只是一个按钮不居中、一个弹窗被遮住、一个列表横向溢出，改着改着就开始试 position、试 z-index、试 overflow: hidden。最后页面看起来对了，但原因不清楚，下次一改又坏。

我以前也喜欢“试出来”。后来踩多了才发现，CSS 排查需要顺着浏览器的布局规则走，不然就是碰运气。

先确认盒子在哪里

布局问题第一步，不是改样式，而是看盒子。

打开 DevTools，选中元素，看：

  • 它实际宽高是多少
  • margin / padding / border 是多少
  • 父元素宽高是多少
  • 是否被 overflow 裁剪
  • 是否被 transform 或 position 改了参照系

很多“不居中”其实是父容器宽度不对，很多“没显示”其实是高度为 0，很多“点不到”其实是被透明元素盖住。

flex 问题先看主轴和收缩

Flex 布局里，常见问题是元素被挤压或溢出。

如果标题很长，可能把右侧按钮挤出去。很多人会加 overflow: hidden，但还不够。flex item 默认 min-width: auto，内容不愿意比自身最小内容宽度更窄。

min-width: 0 是 flex 溢出问题里的高频答案。它告诉元素可以收缩到比内容更窄。

另一个常见问题是搞混主轴和交叉轴。justify-content 管主轴，align-items 管交叉轴。主轴由 flex-direction 决定，不一定永远是水平方向。

但如果它所在的 stacking context 比别人低，再大的 z-index 也不一定赢。

会创建 stacking context 的常见属性包括：

  • position + z-index
  • opacity 小于 1
  • transform
  • filter
  • isolation
  • fixed / sticky

如果父元素有 transform，里面的 fixed 元素也可能表现得不像相对视口固定。

overflow hidden 是刀，不是胶水

overflow: hidden 很常被用来“修一下”。

它确实能裁掉多余内容，但也会带来副作用：

  • 下拉菜单被裁剪
  • sticky 失效
  • 阴影被切掉
  • 滚动容器改变
  • 焦点轮廓不可见

如果只是为了解决圆角裁剪图片，可以用在局部容器；如果是为了隐藏布局错误，最好先找出谁撑破了宽度。

横向溢出时，我会先在 DevTools 里找超过视口的元素，而不是直接给 body 加 overflow-x: hidden。后者只是把问题藏起来。

响应式要测极端内容

响应式布局不能只测设计稿里的理想文案。

要测：

  • 长英文单词
  • 超长中文标题
  • 空数据
  • 图片加载失败
  • 浏览器缩放
  • 低宽度手机
  • 大字号设置

很多布局在正常文案下没问题，一换长文本就爆。CSS 要允许内容变化，而不是假设内容永远听话。

我的排查顺序

遇到布局问题，我会按这个顺序：

  1. DevTools 看盒模型和父容器
  2. 确认布局模式：normal flow、flex、grid、position
  3. 看是否有 min-width / min-height 阻止收缩
  4. 查 overflow 和滚动容器
  5. 查 stacking context，而不是盲加 z-index
  6. 用极端内容测试响应式
  7. 最后再决定是否改结构

CSS 不是玄学。它只是规则多，而且规则会叠加。按布局模型排查，比靠试错稳得多。
