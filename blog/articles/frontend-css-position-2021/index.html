CSS 定位为什么总让人绕晕：relative、absolute、fixed 到底怎么配合

2021-02-03
前端基础

CSS 里的定位一直是前端基础里很典型的一类知识点。

概念看起来不多，属性也不复杂，但一碰到真实布局，就很容易出现两个问题：要么定位不到自己想要的地方，要么定位是对了，结果把周围布局全弄乱了。

很多时候不是属性难，而是没有把“元素原来在哪”“它现在相对谁定位”“它是否还占文档流空间”这三件事分开理解。

先理解什么叫文档流

页面元素在默认情况下，会按照 HTML 结构顺序依次排布。

块级元素从上到下，行内元素从左到右，这种自然排布方式通常就叫文档流。

如果一个元素还留在文档流里，后面的元素就会参考它原来的位置排布；如果元素脱离了文档流，后面的元素会当它原本不存在。

定位相关问题之所以容易乱，就是因为不同 position 值对文档流的影响不一样。

relative 常被低估，但它非常实用

`position: relative`` 的一个特点是：元素仍然保留在文档流中，只是可以相对自己原本的位置偏移。

很多人以为 relative 只能拿来“自己挪一下”，其实它还有另一个非常重要的作用：为绝对定位子元素提供参照系。

absolute 真正关键的是“相对谁”

`position: absolute`` 的特点是元素脱离文档流，并且相对于某个定位祖先元素进行定位。

如果它的祖先里有最近的非 static 定位元素，就相对那个祖先；如果没有，通常会相对页面初始包含块。

这也是为什么很多组件都会写成：

父元素 relative，子元素 absolute，这是很常见也很稳的一组搭配。

如果父元素不设参照系，绝对定位元素可能会直接跑到页面别的地方，表现看起来就像“失控了”。

fixed 和 absolute 很像，但参照物不一样

`position: fixed`` 也会脱离文档流，但它通常相对浏览器视口定位。

这类元素不会跟着普通页面滚动一起移动，所以很适合：

  • 回到顶部按钮
  • 悬浮客服入口
  • 固定顶部导航

sticky 像是相对定位和固定定位的结合

现在页面里也越来越常见 position: sticky。

它的行为可以粗略理解成：在没滚到阈值前像普通元素，滚到指定位置后像固定元素。

最典型的场景是：

为什么绝对定位容易把布局搞乱

绝对定位最大的问题，是它脱离文档流。

这意味着你虽然把它放到了想要的位置，但其他元素不会给它留空间。如果一个区域本来应该依赖内容高度撑开，结果你把核心内容都改成了 absolute，父元素高度可能直接塌掉。

很多新手页面里的重叠、遮挡、留白异常，都是因为过度依赖绝对定位。

不是说 absolute 不能用，而是它更适合：

  • 小范围角标
  • 装饰元素
  • 叠层操作区
  • 需要压在内容上的局部模块

如果一个区域本质上还是正常流式布局，用 Flex、Grid 或普通文档流往往更稳。

定位和层级经常一起出现

只要说到定位，通常也会碰到 z-index。

但 z-index 不是所有元素都能直接生效，它和定位上下文有关。很多时候你给元素加了很大的 z-index 仍然没压住别的层，不是数值不够大，而是层叠上下文不在一层。

所以遇到弹窗、下拉框、浮层被遮住的问题时，不能只盯着 z-index，还要往上看定位祖先和层叠上下文。

实战里更重要的是少滥用定位

CSS 定位好用，但它不是通用解法。

早几年我也经常看到一种写法：页面结构一复杂，就开始靠一堆 absolute + top/left 硬摆位置。短期看效果能出来，后期维护会越来越痛苦，响应式一变、内容一变、字体一变，所有坐标都要跟着重调。

所以我现在的判断顺序更简单：

  • 能用正常文档流解决，先不用定位
  • 需要局部覆盖或角标，再考虑 absolute
  • 需要吸顶吸底，再看 sticky 或 fixed
  • 需要子元素相对父元素摆放，先给父元素建立参照系

把定位当作补充工具，而不是默认布局手段，页面会稳定很多。
