数组方法整理：map、filter、reduce 不只是面试题

2019-11-07
JavaScript前端基础

数组方法是前端最常用的基础之一。

列表接口返回数组，页面筛选数组，表格统计数组，菜单树转换数组。面试问 map、filter、reduce，项目里也每天都在用。

关键不是背 API，而是知道每个方法适合什么场景。我带过几个刚毕业的同事，发现大家不是不会用，而是分不清边界——什么时候该返回新数组、哪个会改原数组、回调返回值有没有意义。这些没搞清楚，写出来的代码就会出各种隐蔽 bug。下面这些都是我在公司后台项目里真实写过、也真实修过的代码。

先说一个共同点：除了 forEach 之外，这几个方法都不修改原数组，而是返回一个新结果。这点在 Vue/React 这种依赖数据驱动视图的框架里很重要——你 filter 出一个新数组赋值给 this.list，视图才会更新；你要是直接在原数组上 splice，有时候反而触发不了你想要的响应。先记住这条，后面很多坑都是从「到底改没改原数组」引出来的。

find 和 filter 的区别经常有人搞混：find 返回的是「那个元素本身」，filter 返回的是「装着符合条件元素的数组」。要拿一条记录详情用 find，要拿一批用 filter。如果你只想知道有没有某个元素、不关心是哪个，用 findIndex（返回索引，找不到是 -1）或者后面的 some 更直接。

最后这句的浅拷贝很关键——find 拿到的是列表里那个对象的引用，你直接往上改，列表会跟着变，弹窗还没点保存数据就脏了。这个坑我在表单编辑里踩过不止一次。

some 和 every

some：只要有一个满足就返回 true。

every：全部满足才返回 true。

权限判断、全选状态里很常用。表格的全选框我基本都这么写：勾选状态是 list.every(i => i.checked)，半选（indeterminate）状态是 list.some(i => i.checked) && !全选。两个方法一搭，逻辑特别清楚。

这俩还有个容易被忽略的特性：短路。some 一旦遇到 true 就立刻停下不再往后跑，every 一遇到 false 也立刻停。所以拿 some 替代「找到就 break 的 for 循环」是完全合理的，不会有性能浪费。另外要记牢空数组的边界——空数组 [].some(...) 永远是 false，[].every(...) 永远是 true。我曾经判断「所有项都通过校验」时没考虑列表为空的情况，结果空列表也被判定为「全部通过」放行了，差点出线上问题。

reduce 有个我反复叮嘱新人的坑：初始值别省。第二个参数 0 / {} / [] 一定要写。不写初始值时，reduce 会拿数组第一个元素当累加器、从第二个开始遍历，遇到空数组还会直接抛 Reduce of empty array with no initial value。我们一个统计金额的页面，正好遇上某天数据为空，没给初始值，页面直接白屏报错。加个 , 0 就好了，从此我写 reduce 第一件事就是先把初始值补上。

reduce 很强，但不要滥用。简单 map 或 filter 能表达清楚时，不必硬写成 reduce。我见过有人用 reduce 实现 filter 的效果，逻辑绕了三层，review 的人得盯着看半天才看懂——能用语义更直白的方法就别炫技。我的标准是：如果一段 reduce 让看代码的人需要在脑子里跑一遍才懂，那它就该换成 map/filter 的组合。

链式调用

链式调用清楚，但数据量很大时要注意性能。每接一个 filter/map 都会完整遍历一次数组、再生成一个中间数组，链得越长、数据越大，临时对象越多。多数后台列表也就几十上百条，这点开销完全无所谓，可读性更重要，别提前优化。真到了几万条还要在前端跑复杂转换，我一般会想想是不是该让后端直接返回处理好的数据，或者退回到一个 for 循环里一趟做完所有事。

顺手记一组我常忘要查文档的「会不会改原数组」对照表，免得每次都试：

  • 不改原数组（返回新值）：map、filter、slice、concat、reduce
  • 会改原数组：splice、sort、reverse、push、pop、fill

sort 这个尤其阴——它原地排序还返回原数组本身。我曾经写 var sorted = list.sort(...)，以为留了一份原始顺序，结果 list 自己也被排乱了，原始顺序再也找不回来。要保留原数组，先 slice() 复制一份再排：var sorted = list.slice().sort(...)。还有 sort 默认把元素转成字符串再按字符编码比较，排数字会出乱子：

'10' 的首字符 '1' 比 '2' 小，所以默认排序把 10 排到了 2 前头。排数字必须自己传 (a, b) => a - b，这也是面试高频陷阱。

一个综合的小例子

把这些方法串起来看一个真实需求：一批订单，要算出「已支付订单」按用户分组的总金额。

filter 负责「留谁」，reduce 负责「怎么聚」，各司其职，比一个大 for 循环里塞满 if 要清楚得多。这种「先过滤、再聚合」的套路，我在做报表和统计时几乎天天用。

forEach 做遍历，map 做转换，filter 做筛选，find 找一个，some/every 做判断，reduce 做累积。

面试问数组方法，项目里更要用得准确。选对方法，代码会比手写一堆 for 循环更清楚。
