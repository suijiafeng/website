HTTPS、TLS 和证书：为什么登录页不能再裸奔

2019-09-18
杂项

登录页、后台系统、支付页面如果还跑在 HTTP 上，风险很大。

HTTP 明文传输，网络中间的人可能看到请求内容，也可能篡改响应。HTTPS 不是“地址栏多个锁”这么简单，它解决的是传输安全和身份确认问题。

HTTP 的问题

HTTP 是明文的。

用户提交：

如果网络环境不可信，就可能被看到。

接口响应也可能被篡改。比如页面脚本被插入广告或恶意代码。

HTTPS 做了什么

HTTPS = HTTP + TLS。

它主要解决：

  • 加密传输
  • 身份认证
  • 防篡改

浏览器和服务器建立 TLS 连接后，再在安全连接里传 HTTP 数据。

证书的作用

证书用来证明“这个服务器确实是这个域名的服务器”。

浏览器会验证证书：

  • 是否由可信 CA 签发
  • 域名是否匹配
  • 是否过期
  • 是否被吊销

如果证书有问题，浏览器会给出安全警告。

不要让用户习惯忽略证书警告。内部测试可以临时处理，正式环境必须使用可信证书。

对称加密和非对称加密

简单理解：

对称加密速度快，但双方要共享同一个密钥。

非对称加密有公钥和私钥，适合安全交换信息，但性能成本更高。

TLS 握手会结合两者：用非对称能力协商安全参数，再用对称加密传输大量数据。

混合内容

HTTPS 页面里加载 HTTP 资源，会出现 mixed content。

脚本、接口这类主动内容可能被浏览器拦截。

页面升级 HTTPS 后，静态资源、接口、图片、字体都要一起检查。

Cookie 安全属性

HTTPS 下 Cookie 应该配合：

Secure 表示只在 HTTPS 下发送。

HttpOnly 防止 JavaScript 读取。

SameSite 能减少一部分 CSRF 风险。

前端要注意什么

前端能做的事：

  • 所有接口使用 HTTPS
  • 不在页面里混用 HTTP 资源
  • 不把敏感信息放 URL
  • 登录态 Cookie 配合安全属性
  • 证书错误不要让用户忽略
  • 本地开发和正式环境区分清楚

安全不是只靠前端，但前端是用户入口，不能无视。

小结

HTTPS 解决的是传输过程中的加密、身份验证和防篡改。

面试问 TLS 和证书，项目里更要知道登录页、后台系统、支付页面为什么必须 HTTPS。只要涉及账号和敏感数据，明文传输就不应该存在。
