使用 Tailwind CSS 实现博客在移动端和电脑端的字体适配

2022-03-14 19:32:44
杂项

在进行博客设计时，确保在移动端和电脑端都拥有良好的阅读体验是非常重要的。借助 Tailwind CSS，我们可以轻松实现这一目标。本文将为你介绍如何使用 Tailwind CSS 优化博客的字体设计，并确保在不同设备上获得一致的用户体验。

字体适配不只是“移动端小一点，电脑端大一点”。真正影响阅读体验的因素还有行距、段落间距、内容宽度、标题层级、图片比例和代码块展示。如果只改字号，页面仍然可能在手机上显得拥挤，在大屏上显得一行太长。

这篇文章仍然围绕 Tailwind CSS 来写，但目标不是堆 class，而是建立一套适合博客阅读的排版规则。

1. 基础字体大小设计

在 Tailwind CSS 中，你可以通过 text-base、text-lg 等类来轻松设置不同设备的字体大小。以下是移动端和电脑端的基础字体大小设计建议：

  • 移动端：

    • 正文：text-base（默认是 16px）
    • 一级标题：text-2xl（默认是 24px）
    • 二级标题：text-xl（默认是 20px）
    • 三级标题：text-lg（默认是 18px）
    • 辅助文字：text-sm（默认是 14px）

  • 电脑端：

    • 正文：lg:text-lg（18px）
    • 一级标题：lg:text-4xl（36px）
    • 二级标题：lg:text-2xl（24px）
    • 三级标题：lg:text-xl（20px）
    • 辅助文字：lg:text-base（16px）

通过这种方式，你可以确保博客在不同设备上都拥有适合的阅读体验。

我会先从正文开始定标。博客正文通常不建议低于 16px，因为移动端长时间阅读时，过小字体会明显增加疲劳。电脑端正文可以提升到 17px 或 18px，但不一定越大越好，还要看内容宽度。

标题的变化也要克制。移动端如果 h1 太大，首屏会被标题占满；桌面端如果标题太小，层级又不够明显。所以比较稳的做法是移动端保证紧凑，桌面端适当拉开层级。

2. 响应式设计

借助 Tailwind CSS 的响应式工具，你可以为不同的设备屏幕设置不同的样式。在 Tailwind 中，默认提供了几个断点：

  • sm：640px 及以上
  • md：768px 及以上
  • lg：适用于 1024px 及以上的设备（电脑端）
  • xl：适用于 1280px 及以上的设备（大屏幕）

这里有一个容易误解的点：Tailwind 默认是移动端优先。没有前缀的类会先作用在所有屏幕上，带 md:、lg: 的类会在达到对应断点后覆盖。

例如 text-base lg:text-lg 的意思是：默认使用 text-base，当屏幕宽度达到 lg 后使用 text-lg。它不是“lg 以下生效”，而是“lg 及以上生效”。

3. 自定义行距

行距要和字号一起看。字号变大后，如果行距没有跟着调整，段落会显得拥挤；行距过大，又会让阅读节奏断开。

4. 控制阅读宽度

大屏适配时最容易忽略的是内容宽度。

如果文章容器在 1440px 屏幕上直接铺满，一行文字可能非常长。行太长会让眼睛换行困难，阅读体验会变差。博客正文通常需要限制最大宽度：

max-w-3xl 能让正文保持在比较舒适的宽度，mx-auto 让内容居中，px-4 保证移动端左右不会贴边。

如果页面里有目录、侧边栏、代码示例，就要根据布局重新计算正文宽度。不要只看整页宽度，要看真正承载阅读内容的那一列。

9. 结论

借助 Tailwind CSS 的灵活性，你可以通过响应式工具轻松调整博客在不同设备上的字体大小、行距和媒体展示效果。无论是移动端还是电脑端，你的博客都将拥有良好的视觉层次感和阅读体验。

通过以上方案，你可以确保博客在各种设备上都有一致的视觉效果和用户体验。这种基于 Tailwind CSS 的解决方案，不仅简洁易用，还能够根据需要快速调整和优化布局。

我现在做博客排版时，会先定正文，再定标题，再定容器宽度，最后处理图片、代码块和辅助信息。字体适配不是孤立的字号问题，而是一套阅读体验问题。
