Sass 和 BEM 写组件样式：命名清楚比嵌套更重要

2018-07-15
CSS前端基础

组件化之后，CSS 最大的问题不再是“能不能写出效果”，而是“样式会不会互相影响”。

Sass 提供变量、嵌套、mixin，BEM 提供命名约定。两者配合得好，样式会很清楚；配合不好，嵌套会越来越深，类名会越来越难读。

不推荐：

嵌套太深会让选择器权重变高，后面覆盖困难。

我习惯控制在 3 层以内。组件样式优先靠类名，而不是靠 DOM 层级。

变量管理颜色和间距

使用：

变量不是越多越好。只把真正全局复用、设计上稳定的值抽出来。某个页面特有的颜色，不一定要进全局变量。

状态类要明确

不要依赖复杂选择器表达状态：

状态应该直接体现在类名上，这样 JS 切换也更清楚。

mixin 要少用

mixin 很方便：

但如果 mixin 里塞很多样式，调用方会看不出最终生成什么 CSS。

适合抽 mixin 的通常是浏览器前缀、常见布局、1px 边框这类稳定模式。业务样式不要过度 mixin 化。

小结

Sass 和 BEM 解决的是样式可维护性。BEM 让类名有归属，Sass 让变量和复用更方便。

真正要注意的是克制：嵌套别太深，变量别太碎，mixin 别太黑盒，状态类要明确。样式写得清楚，比写得短更重要。
