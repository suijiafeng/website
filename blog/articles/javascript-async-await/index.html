掌握JavaScript异步编程

2024-09-07
前端基础

JavaScript 的异步编程能力是它最重要的基础能力之一。只要写过前端项目，就绕不开接口请求、定时器、文件上传、图片加载、用户输入防抖、服务端渲染数据获取这些场景。

很多人学习异步时，会停在 async/await 的语法层面：知道 await fetch()，知道 try/catch，但一到实际项目就开始困惑：多个请求应该串行还是并行？一个请求失败是否要影响其他请求？用户切换页面后旧请求要不要取消？接口错误结构不统一时前端怎么处理？

这篇文章从基础语法讲起，但重点放在项目里真正会遇到的边界。

为什么需要异步编程

JavaScript 运行在单线程模型上，浏览器主线程既要执行脚本，也要处理渲染、用户输入和事件回调。如果一个耗时任务一直占着主线程，页面就会卡住。

异步编程的核心价值是：把需要等待的事情交出去，等结果回来时再继续处理。

常见异步任务包括：

  • 网络请求
  • 定时器
  • 文件读写
  • IndexedDB 操作
  • 图片、字体、脚本资源加载
  • Web Worker 计算结果返回
  • Node.js 中的数据库和文件系统调用

需要注意的是，异步不等于并行。setTimeout、fetch、事件监听这些 API 会把回调安排到未来执行，但 JavaScript 代码本身依然遵循事件循环规则。理解这一点，才能解释为什么一个长时间运行的同步循环依然会让页面假死。

小结

异步编程不是只会写 await 就够了。回调、Promise、async/await 解决的是表达方式；并行控制、取消请求、超时处理、错误归一化解决的是工程可靠性。

我的判断标准很简单：先看任务之间有没有依赖，再决定串行或并行；再看结果是否可能过期，决定是否需要取消；最后统一错误结构，让调用方不用猜。把这几件事做好，JavaScript 异步代码会从“能跑”变成“可维护”。
