前端请求取消和竞态：旧请求不能覆盖新页面

2022-04-08
前端基础JavaScript

前端请求最常见的隐蔽 bug，是旧请求晚回来，覆盖了新状态。

比如搜索框里先输入 a，请求 A 发出去；马上输入 ab，请求 B 发出去。正常应该显示 ab 的结果。但如果 A 比 B 晚返回，页面可能又变回 a 的结果。

这类问题在本地不一定稳定复现，但线上网络一抖就会出现。解决它不能只靠“接口应该很快”，前端要处理请求生命周期。

竞态不只发生在搜索

常见场景包括：

  • 搜索输入连续变化
  • 切换 tab 时加载不同列表
  • 路由 id 快速变化
  • 弹窗打开后又关闭
  • 上传中用户取消
  • 页面卸载时请求还没结束

如果旧请求完成后还能修改当前页面，就有风险。

API 错误要分类型

请求取消、网络失败、业务错误要分开。

取消不提示，网络失败可重试，业务错误回填字段，未知错误上报。所有错误都弹同一句话，用户很难处理。

我的请求取消清单

我会检查：

  • 连续搜索是否会旧结果覆盖新结果
  • 切换路由或 tab 时旧请求是否还能写状态
  • 组件卸载时请求是否取消或忽略
  • AbortError 是否被当成正常取消处理
  • 防抖是否配合竞态保护
  • API 错误是否区分取消、网络和业务错误

请求不是发出去就结束。用户操作比网络返回快得多，前端必须保证最后展示的是当前页面需要的数据，而不是最晚返回的数据。
