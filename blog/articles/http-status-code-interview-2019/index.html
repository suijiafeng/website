HTTP 状态码：前端联调时不能只知道 200 和 404

2019-08-09
请求与异步前端基础

接口联调时，状态码是前后端沟通的第一层语言。

如果前端只知道 200 和 404，很容易把问题都归成“接口失败”。实际项目里，401、403、304、400、500 的处理方式完全不同。

状态码不是用来背的，它应该帮助我们判断错误发生在哪一层。

304 表示资源没变，浏览器可以继续用缓存。它不是错误。

调试静态资源时，如果看到 304，要知道这是协商缓存命中。

4xx 客户端错误

请求参数有问题。

未登录或 token 失效。

已登录但没有权限。

资源不存在。

前端对 401 和 403 要区分。401 通常跳登录，403 应该提示无权限或显示权限页。

5xx 服务端错误

服务端异常。

这些常见于网关、代理、服务不可用或超时。

前端遇到 5xx，通常只能提示用户稍后重试，同时上报错误。不要把 500 当成表单校验失败。

小结

HTTP 状态码能帮助前端判断问题类型：2xx 成功，3xx 重定向或缓存，4xx 多是请求或权限问题，5xx 是服务端或网关问题。

面试问状态码，项目里更要用好状态码。401、403、404、500 不应该都提示“系统异常”，它们代表完全不同的处理路径。
