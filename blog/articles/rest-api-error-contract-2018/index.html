前后端接口错误约定：message 不能每个接口都不一样

2018-09-18
前端基础构建与模块化

前后端联调时，最消耗人的不是正常数据，而是错误。

有的接口失败返回 { message }，有的返回 { msg }，有的返回字符串，有的 HTTP 200 但 code 不为 0，有的直接 500 HTML。前端每接一个接口都要猜一次错误结构。

接口错误如果没有约定，页面体验一定会乱。

HTTP 状态码和业务 code 要分工

HTTP 状态码表达协议层：

  • 401 未登录
  • 403 无权限
  • 404 不存在
  • 500 服务异常

业务 code 表达业务层：

  • 名称重复
  • 库存不足
  • 验证码错误
  • 状态不允许操作

不要所有错误都返回 HTTP 200，也不要所有业务错误都直接 500。状态码乱了，前端、网关、日志都会难处理。

小结

接口错误约定是前后端协作的基础。成功结构、错误结构、HTTP 状态码、业务 code、字段错误都要提前说清楚。

前端最怕的不是接口失败，而是每个接口失败得都不一样。错误结构稳定，页面体验和代码维护都会好很多。
