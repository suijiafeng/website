滚动驱动动画入门：让页面动画跟着滚动走

2022-03-24
前端基础CSS

很多网页都会做滚动相关动画。

比如页面滚动时进度条变长、标题吸顶、图片视差移动、内容逐步出现。

过去这类效果通常依赖 JavaScript 监听滚动位置，再手动修改元素样式。

滚动动画本身不新，但它很容易从“增强体验”变成“制造负担”。所以讨论这类效果时，我更关心两个问题：动画是否真的服务内容，以及实现方式是否会给性能和维护带来过多成本。

传统 JavaScript 写法不是不能用，而是需要写得很谨慎。至少要避免在 scroll 回调里频繁读写布局属性，尤其是同时读取 offsetHeight、getBoundingClientRect，再写 style。读写交错会增加浏览器重新计算布局的压力。

什么是滚动驱动动画

滚动驱动动画的核心思想是：动画进度不再由时间决定，而是由滚动位置决定。

普通动画是“3 秒内从 0 到 100%”。

滚动动画是“页面从顶部滚到底部时，从 0 到 100%”。

这样用户滚得快，动画就快；用户停下，动画也停下。

这里要区分两类效果：

  • 跟随整个页面滚动进度，比如阅读进度条
  • 跟随某个元素进入视口的进度，比如图片进入时淡入、卡片移动

前者更像页面级时间线，后者更像视口级时间线。实现时如果把两者混在一起，动画就容易出现触发位置不准确、移动距离难调的问题。

适合哪些场景

滚动驱动动画适合：

  • 页面阅读进度条
  • 图片视差效果
  • 内容进入视口时变化
  • 横向滚动展示
  • 长页面中的分段动画

这些效果的共同点是：动画和滚动位置强相关。

我会按需求强度选择实现方式：

  • 只需要进入视口后出现：优先 IntersectionObserver
  • 需要跟随页面整体进度：考虑 CSS 滚动时间线或简单滚动计算
  • 需要复杂分段、编排、多元素联动：考虑成熟动画库或明确的状态机

不要把所有滚动效果都写成全局 scroll 监听。页面里滚动相关逻辑一多，后期很难判断哪个监听器影响哪个元素。

使用时要保持克制

滚动动画很容易做得过多。

如果一个页面里每滚动一点都有大量元素移动、旋转、缩放，用户会觉得累，性能也可能变差。

比较好的原则是：

  • 用在关键视觉反馈上
  • 动画幅度不要太夸张
  • 不要影响正文阅读
  • 保留无动画时的基本可用性

动画是增强体验，不应该成为阅读障碍。

兼容和降级

滚动驱动动画的 CSS 新能力仍然需要关注浏览器支持。实际项目里不要假设所有用户都能使用最新语法。

比较稳的策略是：

  • 内容默认可见，不依赖动画才出现
  • CSS 新特性只作为增强
  • 关键反馈提供 JavaScript 或静态降级
  • 不把核心操作藏在动画里

比如阅读进度条没有显示，用户仍然能正常阅读文章；卡片没有淡入动画，内容也应该直接可见。这样新能力即使不生效，也不会影响核心体验。

小结

滚动驱动动画让 CSS 能直接表达“动画跟随滚动进度”这类关系。

它可以减少一部分滚动监听代码，让进度条、视差和页面动效更清晰。实际项目中仍然要关注浏览器支持，并为关键内容保留稳定的基础体验。

我现在做滚动动画时，会先判断它是“进入视口触发”还是“跟随滚动进度”。前者通常交给 IntersectionObserver，后者再考虑 CSS 滚动时间线或滚动计算。选对模型，比一开始就堆动画代码更重要。
