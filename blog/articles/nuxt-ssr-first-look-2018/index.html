Nuxt 初体验：Vue 项目需要 SEO 时，SSR 不是一句配置

2018-04-03
Vue组件与状态

普通 Vue 单页应用开发体验很好，但遇到内容站、官网、营销页时，SEO 和首屏就会变成问题。

搜索引擎能不能抓到内容，用户打开页面前几秒看到什么，分享出去有没有标题和描述，这些都不是纯 SPA 最擅长的场景。Nuxt 的吸引力就在这里：它把 Vue、路由、服务端渲染和项目约定放到了一起。

head 影响分享和搜索

内容页应该动态设置标题和描述：

如果每个页面都是同一个 title，SEO 和分享体验都会差。

SSR 的接口错误要区分

服务端渲染时接口失败，不能只在浏览器控制台报错。要区分 404 和 500。

如果是服务异常，应该返回 500 或展示错误页，而不是当成空内容渲染。

统一 API 错误结构在 SSR 项目里尤其重要，因为错误会影响服务端响应状态。

部署不是静态文件上传

Nuxt SSR 项目需要 Node 服务运行。它和普通 dist 静态部署不一样。

部署时要考虑：

  • Node 进程管理
  • 环境变量
  • 日志
  • 异常重启
  • 反向代理
  • 静态资源缓存

如果只是纯静态内容，也可以考虑生成静态站点。但只要依赖请求时动态渲染，就要按服务端应用对待。

小结

Nuxt 让 Vue 项目更容易处理 SEO 和首屏，但 SSR 不只是“打开一个配置”。数据获取、错误状态、head、部署方式都会变化。

如果项目是后台系统，普通 SPA 往往足够；如果项目是内容站、官网、需要分享和搜索收录的页面，Nuxt 值得认真评估。
