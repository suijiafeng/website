Vue 过渡动画怎么用才不显得多余：先服务交互，再谈效果

2019-02-15
Vue

Vue 的过渡系统很好上手，所以很多人第一次接触时都会很兴奋，觉得页面终于能“动起来”了。

问题在于，动画一旦脱离交互目的，就很容易从“有帮助”变成“看起来有点多余”。

过渡最重要的作用是补信息

好的过渡通常不是为了炫，而是为了告诉用户：

  • 这个元素刚出现
  • 这个区域已经切换
  • 这个操作正在完成

当动画能补足状态变化时，它就有价值。

比如弹窗出现时，淡入能告诉用户“新的操作层已经打开”；列表项删除时，离场动画能告诉用户“这条数据刚被移除”。这些动画都在帮助用户理解变化。

Vue 让这件事变简单了

<transition> 把进入和离开的状态整理得比较清楚，让你不需要手写太多切换细节。

这对页面交互来说很实用，尤其是：

  • 弹窗
  • 下拉层
  • 列表切换
  • 提示信息

刚上手时我总搞混这几个类名，这里顺手理一遍，因为踩坑基本都跟它们有关：

  • fade-enter：进入的起始状态，元素插入前的那一帧
  • fade-enter-active：进入过程中一直生效，transition 写在这里
  • fade-enter-to：进入的结束状态（Vue 2.1.8+）
  • fade-leave：离开的起始状态
  • fade-leave-active：离开过程中生效
  • fade-leave-to：离开的结束状态

我踩过最典型的坑是只写了 fade-enter 没写 fade-enter-active 里的 transition，结果元素直接「啪」地出现，没有任何过渡。原因是 transition 属性必须挂在 -active 类上，起止状态类只负责描述「从哪到哪」。还有一个是 v-if 控制的元素如果外面没包 <transition>，再怎么写类名都不会有动画——Vue 是靠 <transition> 这个包裹组件去监听子元素的插入和移除的。

滑动过渡适合表达层级变化

如果页面里有抽屉、侧边栏、移动端筛选面板，滑动比单纯淡入更能表达“从侧边进入”的空间关系。

这类动画应该短、明确，不要让用户等面板慢慢滑完才能操作。我一般把这种交互动画控制在 200~300ms 之间，再长就开始显得拖沓。设计稿上有时会标 0.5s 的缓动，看着优雅，真用起来每次点开都等半秒，高频操作的后台用户会很烦。

性能上有个习惯要养成：动画尽量只动 transform 和 opacity，别去动 left、top、width、height。前者只触发合成层，能走 GPU；后者会触发重排（reflow），元素一多就掉帧。上面这个面板用 translateX 而不是 right 就是这个原因。如果想进一步提示浏览器提前准备合成层，可以加 will-change: transform，但别滥用，挂太多 will-change 反而吃内存。

但动画不是加得越多越好

如果每个区域都在动，用户的注意力反而会被打散。

而且某些动画如果处理不好，还会带来：

  • 掉帧
  • 卡顿
  • 响应变慢

所以比起“哪里都能动一下”，更重要的是先问一句：这个动画到底在帮助什么。

有几类场景要特别克制：

  • 高频操作：比如输入、连续筛选、批量选择
  • 长列表滚动：动画太多容易掉帧
  • 管理后台：效率通常比表现更重要
  • 错误反馈：应该清楚直接，不要慢慢出现

动画如果延迟了用户完成任务，就算视觉上好看，也是不合适的。

和异步状态配合

很多过渡不是单独存在的，而是和加载、成功、失败状态一起出现。

mode="out-in" 会让旧内容先离开，新内容再进入，适合状态区域切换，避免两个状态同时堆在一起。如果不写 mode，进入和离开是同时发生的，loading 文案和列表会短暂叠在一起，看着像 bug。还有个对应的 in-out，新内容先进来旧的再走，用得少，主要是有些场景不希望中间出现空白。

注意这里几个分支必须带不同的 key，否则 Vue 会复用同一个节点，过渡不触发。我习惯按状态语义命名 key（loading / error / list），出问题时一眼能看出哪个状态没切过去。

<transition> 一次只能有一个直接子元素，所以这种多状态切换都得靠 v-if / v-else-if 保证同一时刻只渲染一个。如果你写了两个并列的 v-if 都可能为真，控制台会直接报「<transition> can only be used on a single element」。

不过说实话，2019 年做后台和移动端，绝大多数动画 CSS 过渡就够了，JS 钩子留给那种确实需要按帧控制、或者高度自适应展开（CSS 没法直接过渡 height: auto）的场景。height 自适应展开这个老难题，要么用 JS 钩子算实际高度，要么用 max-height 取巧，各有各的坑。

Vue 的过渡能力很方便，但真正决定体验的不是 API，而是你有没有把动画放在合适的位置。

先服务交互，再追求效果，页面看起来会自然很多。

好的过渡应该解释状态变化，而不是抢用户注意力。弹窗、列表、加载状态都可以动，但每一次动都应该有明确目的。
