DOM 事件模型：捕获、冒泡和事件委托为什么总被问

2019-07-05
JavaScript前端基础

DOM 事件模型是老面试题，但一点也不过时。

不管你用 Vue 还是 jQuery，最终点击、输入、滚动这些交互都离不开浏览器事件。框架的 @click、v-on、onClick 说到底都是包了一层的 addEventListener，真出了诡异 bug，框架那层文档帮不了你，得回到浏览器原生事件模型才看得明白。项目里很多问题也和事件有关：按钮点了两次、弹窗点击穿透、父子元素都触发、动态列表按钮没反应、解绑没生效导致内存泄漏。

我印象最深的一次，是一个列表里每行有个「展开」按钮，点按钮要展开详情，点整行要跳详情页。结果点按钮的时候，行的跳转也被触发了，用户一展开就被带走。当时我对着代码看了半天没头绪，后来才意识到这就是冒泡——点击 button 的事件冒泡到了 row 上，把 row 的 handler 也触发了。理解捕获和冒泡之后，这类问题排查起来就有章法了，不再是靠瞎试 stopPropagation。

事件流三个阶段

一次点击大致会经历：

  1. 捕获阶段：从 window 往目标元素走
  2. 目标阶段：到达真正点击的元素
  3. 冒泡阶段：从目标元素往外冒泡

passive: true 这个我在移动端列表卡顿优化时帮了大忙——以前滚动监听不加 passive，浏览器为了等你可能 preventDefault 会推迟滚动，体感就是滑动一卡一卡的，加上之后立竿见影。不过要注意兼容性，老浏览器不认配置对象会把它当 true（捕获），所以要先做特性检测，或者用 addEventListener('touchmove', h, false) 兜底。

大多数业务代码用冒泡就够了。捕获用得少，但有个场景它无可替代：你想在事件到达目标元素之前就拦截，比如做一个全局的「点击任意位置先记录埋点再说」，或者要抢在子元素自己的 handler 之前处理，这时候在外层用捕获绑定就能比冒泡更早拿到事件。我做过一个全局快捷键屏蔽，就是在捕获阶段拦下来的。

target 和 currentTarget

event.target 是真正触发事件的元素，可能是 button。

event.currentTarget 是当前绑定事件的元素，这里是 ul。

事件委托里不要混淆这两个。我刚开始写委托时就栽过：在绑定到 ul 的 handler 里写了 event.currentTarget.dataset.id 想拿被点击那一项的 id，结果永远拿到的是 ul 的，因为 currentTarget 在整个 handler 里恒等于绑定者。要拿真正被点的元素得用 target。

还有一个更隐蔽的坑：currentTarget 只在事件处理过程中有效，事件跑完它会被置为 null。如果你在 handler 里 setTimeout 或者 Promise.then 异步访问 event.currentTarget，拿到的就是 null。我有次在异步回调里用它，控制台一直报 Cannot read property of null，查了好久才反应过来是这个机制。要在异步里用，提前把它存到一个局部变量里：

阻止冒泡

它会阻止事件继续向外冒泡。

点击遮罩关闭，点击弹窗内容不关闭。这是 stopPropagation 最经典的用法：遮罩和弹窗内容在 DOM 上是父子，点内容会冒泡到遮罩触发关闭，给内容加一道 stopPropagation 把冒泡掐断就行。

不过这个弹窗写法我后来不太用了，因为它有个隐患：内容区里如果还有用事件委托的逻辑（比如内容里有个列表也委托给某个外层），你这一刀 stopPropagation 可能把它一起切断。更稳的写法是不拦冒泡，而是在遮罩的 handler 里判断点的到底是不是遮罩本身：

不要随便阻止冒泡。父级如果依赖事件委托，子元素阻止后父级就收不到事件——这是 stopPropagation 最坑的地方，它的副作用是「隔空」的，你在子组件里加一行，可能让八竿子打不着的某个外层委托失灵，排查时根本想不到是它。我们团队后来的约定是：能用 event.target 判断解决的，就不要用 stopPropagation；非用不可的，必须写注释说明拦的是什么、为什么拦。

另外提一个相关但更狠的：stopImmediatePropagation。stopPropagation 只是不往外冒，但同一个元素上绑的其他 handler 还会执行；stopImmediatePropagation 连同元素上后续的 handler 也一并掐掉。这个用得极少，但知道有这么个东西，碰到「同一元素绑了多个 handler 想只跑前面的」时能想起来。

小结

DOM 事件模型看起来基础，但项目里很常用。捕获、冒泡、事件委托、target、currentTarget、阻止默认行为、解绑，这些都是交互代码的底层能力。

面试喜欢问它，是因为它能看出你是否真的理解浏览器事件，而不是只会写框架语法。
