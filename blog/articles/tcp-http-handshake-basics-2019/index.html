TCP、HTTP 和三次握手：前端也要懂一点网络基础

2019-10-29
请求与异步前端基础

前端平时写的是页面和请求，但请求为什么慢、为什么会超时、为什么 HTTPS 第一次连接更贵，这些都离不开网络基础。

面试里问 TCP 三次握手、HTTP 状态码、HTTPS，也不是要前端去写网络协议，而是希望你知道浏览器发一个请求背后发生了什么。

一个请求大致经历什么

用户打开页面时，浏览器可能会经历：

  1. DNS 解析域名
  2. 建立 TCP 连接
  3. 如果是 HTTPS，进行 TLS 握手
  4. 发送 HTTP 请求
  5. 服务端处理并返回响应
  6. 浏览器接收响应并渲染

任何一步慢，页面都会慢。

TCP 三次握手

建立连接需要三次握手：

简单理解：

  • 客户端告诉服务端：我要建立连接
  • 服务端告诉客户端：我收到了，也准备好了
  • 客户端再确认：我也知道你准备好了

这样双方都确认发送和接收能力正常。

Keep-Alive

如果每个请求都重新建立 TCP 连接，成本很高。

HTTP Keep-Alive 可以复用连接：

浏览器可以在同一个连接上发送多个请求，减少握手成本。

这也是为什么资源合并和连接复用一直是性能优化里重要的一部分。

HTTPS 多了什么

HTTPS 在 HTTP 和 TCP 之间加了 TLS。

它解决：

  • 加密传输
  • 身份认证
  • 防止中间人篡改

代价是连接建立更复杂。好在连接复用和缓存能减少影响。

涉及登录、支付、后台系统，HTTPS 是基本要求。不要在 HTTP 页面里传敏感信息。

前端能做什么优化

前端不能控制所有网络细节，但能做一些事：

  • 减少不必要请求
  • 静态资源使用缓存
  • 合理使用 CDN
  • 接口并行而不是无意义串行
  • 控制资源大小
  • 超时和错误统一处理

请求失败时，要区分网络错误、超时、HTTP 错误、业务错误。

小结

TCP 负责可靠连接，HTTP 负责应用层请求响应，HTTPS 负责安全传输。

面试问三次握手和 HTTP，不是让前端背网络课本，而是让你理解请求不是“瞬间发生”的。连接、传输、缓存、错误处理都会影响页面体验。
