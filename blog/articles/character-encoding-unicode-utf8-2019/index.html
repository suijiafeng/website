字符编码、Unicode 和 UTF-8：乱码问题不是玄学

2019-06-02
前端基础

乱码问题很烦。

页面中文显示成一堆奇怪字符，接口参数传过去变了，下载 CSV 打开乱码。很多时候不是业务逻辑错，而是编码没对齐。

字符编码是很基础的计算机知识，前端也经常遇到。

ASCII

ASCII 最早只覆盖英文字符、数字和一些符号。

它不够表示中文。

Unicode

Unicode 的目标是给世界上各种字符分配统一编号。

比如“你”“好”都有自己的码点。

但 Unicode 只是字符编号标准，不等于具体存储方式。

UTF-8

UTF-8 是 Unicode 的一种编码方式。

它是变长编码：

  • 英文通常 1 个字节
  • 中文通常 3 个字节

常见排查顺序

乱码时先查：

  1. 文件保存编码是不是 UTF-8
  2. HTML meta 是否声明 UTF-8
  3. 响应头 charset 是否正确
  4. 接口传参是否 encode
  5. 后端读取和数据库编码是否一致

不要只改前端。编码链路上任何一环不一致，都可能乱码。

小结

Unicode 负责统一字符编号，UTF-8 是常用编码方式。网页、接口、文件、数据库都要对齐编码。

面试问编码，项目里遇到乱码时也真用得上。乱码不是玄学，按文件、响应头、传参、存储这条链路查，通常能定位。
