npm scripts 项目工作流：把常用命令写进 package.json

2018-07-29
构建与模块化

前端项目里，package.json 不只是依赖清单，也是团队工作流入口。

如果常用命令散在 README、聊天记录和个人习惯里，新人接手项目会很痛苦。把开发、构建、测试、检查都写进 npm scripts，项目会清楚很多。

pre 和 post 钩子

npm scripts 支持前置和后置：

执行 npm run build 时，会先跑 prebuild，再跑 build，最后跑 postbuild。

这个能力适合做必要检查，但不要把流程藏得太深。否则有人执行一个命令，结果触发很多意料之外的步骤。

脚本命名要有规律

主命令短，扩展命令用冒号。

不要出现 build-prod、build_test、buildAnalyze 混用。命名统一，本身就是文档。

不要让脚本吞错误

危险写法：

lint 失败还继续构建，会让质量检查失去意义。

除非非常明确允许失败，否则脚本应该让错误直接暴露出来。

小结

npm scripts 是项目工作流的门面。开发、构建、测试、检查都应该有统一入口。

命令要清楚，命名要统一，跨平台要考虑，关键步骤不要吞错误。一个好用的 package.json，能减少很多沟通成本。
